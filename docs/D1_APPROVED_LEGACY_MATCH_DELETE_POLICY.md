# D1移行確定仕様：試合の物理削除・完全アーカイブ・管理者による明示的復旧

承認日：2026/11/21。第19工程のA/B質問に対して、ユーザーは明示的に**A（既存GASの削除仕様を維持）**を選択した。

## 維持する確定仕様

- 既存GASの `matchDeletePlan_` / `matchDeleteExecute_` / `matchDeleteArchiveStatus_` と `MATCH_DELETE_TABLES_` が基準。対象日程の試合セッション（5列）、全試合版（9列、旧7列互換は別途扱う）、操作履歴（7列）を元の**行番号を含めて** `{rowNumber,cells}` として `targets` に保存する。未失効の閲覧リンク（6列）も `links` に退避する。アーカイブに `schema:1,practiceId,sessionVersion,settingsVersion,targets,links` を保持する。
- 先にアーカイブを確実に保存し、未失効の閲覧リンクを失効し、試合版本体・操作履歴・試合セッションを**物理削除**する。D1移行先でも削除済み試合をアクティブデータに残して「非表示だけ」としない。
- 復旧は**管理者による明示的・監査可能な操作だけ**で行う。削除直後の自動復元・利用者による自動復元・リンクの自動再有効化は禁止。アーカイブの構造/チャンク/SHA/元記録の同一性の検査を終えるまで、復旧書込を行わない。
- D1では第16工程で承認された操作ID別対象の流用禁止（B）を維持する。第17工程で承認された監査失敗時の**一括ロールバック（B）**も維持し、アーカイブ・リンク失効・物理削除・操作結果が矛盾した状態で確定しない。旧GASの複数Spreadsheet操作間の中断窓をD1側のトランザクションで狭めるが、業務上の物理削除と手動復旧の意味は変えない。

## 保留・禁止

- 第19工程の論理削除（tombstone）と、通常APIからの自動復元の技術候補を**正式なD1業務仕様として採用しない**。第19工程のコードは古い架空実験として履歴を維持し、新機能として本番経路に接続しない。
- 現行GAS、47 GAS_ONLY業務API、公開Worker、LINE/LIFF、実Google Sheets/バックアップ、実データや個人情報・領収書、旧46件SHA不一致版（現役8/アーカイブ38）、本番は変更しない。旧SHAを正当化・上書き・移送しない。
- 今回の架空技術実証では、実Google Sheetsの「物理行番号」は保持できないため、**明示的に架空の sourceOrder/rowNumber だけ**を使用する。旧46件の復旧が可能になったとは主張しない。復旧プレビューは読取のみとし、本人管理・権限・Google Drive/閲覧リンク・削除アーカイブの運用復旧が整うまで書込APIを作成しない。
- D1以降の実移行時のアーカイブの保持期間、削除依頼対応・暗号化/アクセス権限/復旧責任、監査・日程削除と収支/権限の整合性は今後の追加判断事項。本番切替は別途明示事前承認必須。
- 性能改善とLINE機能開発はD1マイグレーション完了後まで保留。

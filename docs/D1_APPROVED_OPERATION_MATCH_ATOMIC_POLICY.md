# D1移行確定仕様：操作IDの対象一致と試合更新・監査履歴の完全原子化

**承認日：2026/11/21**。ユーザーの第16工程に対する明示承認：**①B、②B**。根拠：`docs/SESSION_HANDOFF.md`第103節、`docs/SPEC_PRIORITY_POLICY.md`、`docs/D1_PHASE12_ATOMIC_CANDIDATE_AND_APPROVAL.md`、最新GAS `gas-staging/コード.gs`の`auditExisting_`・`matchCommit_`。

## 対象と優先順位

これは**D1移行先の確定業務仕様**。旧GASと動作差があることをレビューしてユーザーが明示的に選んだ例外であり、旧GASの現在の挙動そのものを無断で書き換えない。既存会計・LINE・リッチメニュー・退会・会員/権限、各APIの現在の運用動作はマイグレーションと切替が正式に承認されるまで維持。

### 決定①：操作IDの別対象再利用はB（厳格拒否）

- 現行GASの `auditExisting_` は既存操作IDの**操作種別と操作者のみ**を照合し、対象IDが異なっていても既存結果を返し得る。
- D1移行後は**同じ operationId に対する操作種別・操作者・対象ID**を一体で紐づけ、すべて一致した場合に限り既存の確定済み結果を無書込みで再現する。**対象IDが異なる場合は `CONFLICT/OP_ID_REUSE` として拒否し、対象・操作履歴を更新しない**。
- 同じIDで操作種別/操作者が異なる場合も拒否（既存の拒否仕様を維持）。タイムアウト後の再送/同時送信は同一結果を再現し、二重登録・二重集金しない。複合対象（集金の日程ID+参加者IDなど）は衝突しない正規の複合対象識別子を設計し、単なる参加者名などで判定しない。
- 各D1 APIが正式に揃うまで既存47 `GAS_ONLY` の振り分けを変えない。旧操作履歴のIDに欠損・重複・target不一致がある場合は推測で補正せず移行をブロックする。

### 決定②：試合保存後の監査追記失敗はB（全体ロールバック）

- 現行GASの `matchCommit_` は**新しい版を staging→ready と保存し、有効版ポインタを切り替えたあと**、試合操作履歴の追記失敗をログに残しても新しい有効版を維持し得る。
- **D1移行後は試合版、ready状態、有効版ポインタ/セッション版数、試合操作履歴と操作IDの冪等性を1回の原子的コミット境界に含める**。履歴の一意性違反や書込失敗・制約不一致が発生した場合、**有効版切替・版本体・履歴のすべてを巻き戻し、旧有効版を保持**する。
- 対象の再送時は操作ID照合から既存確定結果を返し、新規版を重ねない。新規版の保存途中・監査失敗・競合0件更新を成功と判定しない。
- D1 Workerの `db.batch()` は原子的なSQLコミットを提供するが、**Worker JSの外側で段階的に read→compute→write しても一つのトランザクションにはならない**。前提・競合・履歴についてSQL条件を確認し、更新件数も照合する。エラー時は旧有効版と操作履歴が不変であることを検査する。
- 既存架空スプレッドシートの試合SHA 46/46不一致は別の移行禁止事項。SHAを再計算して正しいものとして上書きしたり、版を読み飛ばして切替えたりしない。元のJSON/UTF-16分割、履歴、リンク、操作順のロスレス検証が必要。

## 現時点の変更範囲（第17工程）

- **実装可能**：既存の独立した架空専用Worker `zenryoku-smash-d1-atomic-fixture-worker-stage` と架空専用D1 `zenryoku-smash-d1-atomic-fixture-stage` に**別名のテスト専用表**だけを設け、操作ID/対象一致と試合更新・監査失敗全巻戻しをWorker-native SQLで確かめる。オフラインSQLite候補/回帰も確定仕様へ更新する。
- **変更しない**：旧GAS、既存Worker `zenryoku-smash-staging-api`、read-only pilot、元検証D1の業務20表0行、既存47 API、Google Sheets/非共有原本・バックアップ、LINE/LIFF、既存URL・ID・Secret、本番。
- **禁止**：本番データや個人情報の移送、旧試合SHAの補正、本番リリース、業務表への先行書込、正式な認証/権限をテスト用Bearerで置き換えること。
- 回帰検証では旧GASの挙動を**現在は変えず**、D1移行先に限って承認済みB仕様を検証する。既存仕様と承認例外の対象範囲を混同しない。

# D1第10工程：試合版の整合性・アーカイブ履歴・安全なバックアップ実行計画

作成：2026/11/21。参照：検証main `e929fda97490b3a320a347675960081b32b5859c`、`README.md`、`docs/SESSION_HANDOFF.md`第84節、`docs/SPEC_PRIORITY_POLICY.md`、`gas-staging/コード.gs` の `matchHash_`/`matchLoad_`/`matchCommit_`／`matchDeleteExecute_`、第8/9工程、GAS旧試合回帰テスト。**本工程は架空fixtureのオフライン実装と原本の読み取り専用調査であり、業務データ移送・原本修正・本番反映の承認ではない。**

## 1. 不一致の意味を正確に整理

**検証用v0.15シートはガイドに「架空データ、ヘッダーとデータを初期配置済み、setup関数を実行しない」と記載されている。** このシートは現在の本番会計データの正本ではない。

現行GASの試合版保存は、(1) `JSON.stringify(state)`、(2) `Utilities.computeDigest(SHA_256, json)`、(3) UTF-16 30,000単位で分割し一度`staging`として書込、(4) Sheet `getValues()`で読み戻したチャンクのSHAを計算し一致した場合に`ready`化、(5) 最後に`試合セッション`の有効版ポインタを更新、(6) 試合操作履歴を追記、という順序。読み出し`matchLoad_`は`ready`、チャンク数、practiceId、SHA、JSONを検証する。**ハッシュ不一致のまま正常な保存を完了する設計ではない**。ただし旧GASや過去の人手/別ツールの投入・編集履歴があるため、原因を「現行GASの不具合」または「初期fixture不備」と決めつけない。

前工程のスプレッドシート読取専用監査では現存試合版8/8件、内有効版1件の本文SHAと保存SHAが一致しなかった。前工程の独立既知ベクトル検算と、Sheetの`userEnteredValue/effectiveValue`および値取得APIの一致は記録済み。この事実は「現在の試合版を元ハッシュのまま**完全性検証済みD1レコードとして採用してはいけない**」ことを意味し、**架空データだけで実サービス全体の試合状態が破損したと断定しない**。

さらにGoogle Driveの**読み取り専用**版履歴の取得可能な41改訂をメタデータで確認。2026/11/19 05:21〜22:38 **UTC**（JSTでは11/19 14:21〜11/20 07:38）の旧リビジョン4件（#537/#552/#602/#618）の取得内容には現行試合版IDの一致を確認できない一方、レコード本文の差分・生成方式までは確定していない。版内容の追加取得はプロバイダ制限（HTTP 429）で停止した。**日付・作者・修復方法の確定には使わない**。シートに修復用JSON/ハッシュを無断上書きすることを禁止。

## 2. 今回実装する安全なD1試合移行判定（架空値専用）

- `d1-staging/phase10/match_preflight.py` は外部接続・ファイル保存・ログ出力がない純粋関数。明示的な`scope="fabricated_offline_only"`以外を拒否。
- 9列版のチャンク数（最大30）/UTF-16単位数（1セル最大30,000）/index重複/同一版のpracticeId・operationId・SHA・stage、連結時のサロゲート境界、SHA-256 UTF-8とJSON本体を検証。
- 各`試合セッション.activeRevisionId`は**検証成功した**同じ練習日の版だけを参照できる。版の`sessionVersion/settingsVersion`とセッション側を比較する。古い版をactiveと誤認しない。
- `試合操作履歴`の操作ID重複を拒否。**履歴の欠損だけでは試合版を捨てない**：現行`matchCommit_`はポインタ更新後の操作履歴追記失敗をcatchしており、正常コミットでも試合操作履歴がない可能性がある。欠落は警告と別途照合に回し、架空履歴を生成しない。
- 結果は件数・不整合の**コードと件数のみ**。revisionId、operationId、practiceId、JSON本文、名前、LINE ID、SHA、財務額を返さず、printしない。`BLOCKED`または`CANDIDATE_ONLY`の判定だけで、全て緑でも`write_authorized=false`/`cutover_authorized=false`。
- `tests/check-d1-phase10-match-preflight.py` では架空で複数版（旧版と有効版）、絵文字のサロゲート境界を跨ぐチャンク、本文SHA不一致、重複/欠落、`staging`、有効版孤立、クロス日程、版数不一致、操作ID重複、ポインタ切替後の監査未追記を検証。
- 旧7列単一版・削除アーカイブの`completed/prepared`からの復旧は、第8/9工程の既存ゲートと正式原本保全に残す。**既存ロジックや新D1 schemaを無断緩和しない**。

## 4. 残存ゲートと仕様変更なし

- **BLOCKED**：検証用試合版8件のSHA不一致と生成経緯未確定。架空データの作り直しと実業務試合データの修復は別件であり、無断で混同しない。
- 旧試合削除アーカイブ（ハッシュ無し）は日程/参加/集金/会計・旧ユーザー履歴と同時点に整合する独立バックアップが必要。
- チーム所属の物理重複/状態導出、Sheets型混在/DateのJST、全体収支の確定順序・残高・最終管理者/退会、操作IDによる冪等性、D1書込境界/トランザクションとRead Shadowは未完了。
- コード/CI/Docs以外の**GAS/既存・独立Worker/LIFF/旧Sheet/Cloudflare D1業務レコード・Secret/URL/ID/本番は変更しない**。現行全47 APIは`GAS_ONLY`、性能改善・LINE機能拡張はD1移行完了後まで保留。

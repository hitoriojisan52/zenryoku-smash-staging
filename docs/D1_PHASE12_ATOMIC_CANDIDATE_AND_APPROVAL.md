# D1第12工程：会計・集金・対戦表の原子的更新候補と検証用バックアップ承認ゲート

**この段階は架空値・ローカルメモリSQLiteを使用した設計候補であり、既存GAS/Worker/LIFFやCloudflare上のリモートD1にコード/業務データ/DDLを書き込むものではない。既存47 APIはGAS_ONLY。** 検証用v0.15スプレッドシートで確認済みの試合版SHA不一致8/8（有効版を含む）は引き続き移行禁止。未承認の修復や架空データの無断補充は禁止。

## 1. 現行GASから保護すべき業務制約

| 対象 | GASの確認済み実装 | 第12工程の候補検査 |
|---|---|---|
| 本人/権限 | `dispatch_`が共有SecretとLINE userId/登録会員を確認。`requireDuty_`は当番・管理者に限る。管理者優先・チーム有効/所属有効 | 架空会員に限定してroleを再評価。**LINEトークンの真贋を検証したことにはしない** |
| 会計順序 | `ledgerChronologyCompare_`：日付→opening/practice/reimbursement/other→rowId。同日も先行未確定があれば確定禁止 | その順序で並べ直し、先行未確定・未来日確定を拒否 |
| 確定解除 | 現行`mutateLedger_`のunlockは管理者のみ。同日を含む後続確定行があれば拒否 | 管理者/後続確定の2条件をDB更新前に再確認 |
| 残高 | `balanceRecalc_`：opening残高を起点に前残高+集金-支出。残高はマイナスを許容、金額は安全な整数。**既に確定した行の残高を変更しない** | 全行を時系列で検算。支払更新後の後続残高と版数を維持、確定済み変動は全体ロールバック |
| 参加/集金 | 現行`setPayment_`は参加者、当日の集金可能性、expectedVersion、出欠区分別料金（member800/student400/visitor1000/duty400/shuttle400、2h:6/8・3h:7/8・4h:1を100円へ切上げ）を確認 | 参加・既存集金状態と最新対象日程を照合。集金・収支・結果監査を同一メモリ内トランザクション化 |

| 試合 | `matchCommit_`はJSONをSHA-256化、staging→読戻し検証→ready→activeRevisionId→試合操作履歴。ロールは当番/管理者、版数/操作IDを維持 | 各チャンク・ready・session pointer・試合操作履歴を同一メモリトランザクションでコミット、失敗で全行ロールバック。新しい版だけ追加し過去版を上書きしない |

## 2. 実装と安全境界

`d1-staging/phase12/transaction_candidate.py` は外部通信・Cloudflare/GAS・Drive呼出し・実データファイル保存を持たないPythonの純粋な試験用サービス候補。`scope="fabricated_offline_only"`を要求し、SQLite接続も**メモリ内DBかつ外部ATTACHなし、FK有効**のものに限定。内部の`BEGIN IMMEDIATE`/commit/rollbackはPython sqlite3上の実験であり、**Cloudflare D1 Worker APIの呼出し構文ではない**。

- `ledger_transition`: 権限・対象・version/CAS・同日も含む確定順・未来日・管理者専用解除と、その結果の`operation_audit`を原子的に検証。
- `payment_transition`: 以前の開催日の確定状態、本人の出欠・料金、既存集金versionと次版、会計入金、後続の残高、確定済残高不変、operationId再実行を検証。**ターゲット版数は1回のみ増加**（元GAS`setPayment_`と`balanceRecalc_`に合わせる）。
- `match_transition`: 有効版を先にSHA検証し、expected session/settings version、過去`appliedOperations`、新しい版の追記・SHA検証・ready・CASポインタ・試合監査を原子的に検証。D1 TEXTへ単独サロゲートを無断保存しないため、新規候補は有効Unicode境界での分割に限定。**既存GASの30,000 UTF-16単位`String.slice`をバイト同一に移植できたことは証明されていない**。旧分割の完全保全は第11工程で別ゲート。
- 戻り値やテスト用データは架空会員・架空金額のみ。一般向けログは合否のみ。システムエラーは識別子を含まないコードのみを返す。

`tests/check-d1-phase12-atomic-candidate.py`は、実SQL候補スキーマ20テーブルをその場のメモリDBへ適用し、**失敗後に全20テーブルの値を照合**。集金後・収支後・監査後、試合分割保存後・ready後・有効ポインタ変更後・監査後に意図的に例外を注入し、支払済フラグだけ立つ・残高だけ変わる・readyだが孤立した試合版が残る・監査だけ残るといった状態がゼロであることを確認する。古い版の保持、再送の再書込0、古いexpectedVersion競合、権限/日付/確定解除、SHA不一致を検査する。

第12工程**合格条件は架空SQLiteにおけるデータ原子性・正当な拒否条件の再現**。D1リモート・LINE認証付きWorker・GASとの完全同値性を合格扱いしない。

## 3. Cloudflare D1での実装時に解決する制約（最新公開資料を確認）

Cloudflare公式のD1 Workers Database APIは`db.batch([preparedStatements...])`を一つのSQLトランザクションとして扱い、ステートメント失敗時には全体をロールバックする。だが、今回のPython `BEGIN IMMEDIATE`内でアプリコードが状態を読んで金額を計算し、そのまま次のSQLを実行する構成を、独立したD1 Worker API呼出し間の原子的トランザクションへ**そのまま置き換えられるわけではない**。後続の本番相当API開発では、事前条件をSQL側で原子的に評価し、0件更新/衝突も必ず失敗として全バッチ拒否する方法と、`operationId`・権限・会計・試合の一括CASと再送時レスポンスを設計し直すこと。

`db.batch`の成功やSQLiteメモリ内テスト成功だけでは、高並行・再送・Worker timeout・未コミット後の応答消失・D1読み取り複製環境での可視性は保証できない。実D1での小規模架空データ・障害/二重送信・認証・復旧演習は**独立した検証用DBと追加のユーザー承認**が必要。

- [公式 Cloudflare D1 Workers `batch()`](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)
- [公式 D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)：リストアはDBを**その場で上書きする破壊的操作**。保持可能期間はプラン次第（Free最長7日/Paid最長30日）で、**長期独立バックアップの代わりにしない**。
- [公式 Google Drive コピー](https://developers.google.com/workspace/drive/api/guides/create-file#copy_an_existing_file)：コピー作成者の所有となり、原本の共有設定は自動継承せず、配置先の共有フォルダの権限が影響する。よってコピー後にアクセスを検証する。

## 4. ユーザー確認が必要な地点：検証専用の原本保全と隔離復旧

以下は**提案**であり、未承認・未実行。本番データのバックアップ作成、原本操作、D1リモートへの業務データ投入、既存47 APIの切替は含めない。

### 第A承認（先行推奨、まずこの範囲のみ）

**対象**：Google Driveにある`全力☆スマッシュ 接続検証用 v0.15（架空データ）`の**1ファイルのみ**。これは試合版SHAに不一致があるため、「不一致を含めた原本そのまま」の証跡コピーとする。非本番とはいえテスターのLINE userId・操作ID等が含まれ得るため、原本同等の機微情報として扱う。

**方法**：既存ファイルは一切変更せず、現接続ユーザーのみが閲覧できる**新規・非共有のGoogle Drive専用フォルダ**を作成してGoogleネイティブ形式でコピーを1つ作る。コピー後の所有者/公開範囲・全21タブ・シートID/隠しタブ・セル型/数式/日付・参照/ハッシュ・物理行順を**読取専用で**照合し、不一致と欠落は件数だけ報告する。元ファイルとコピーのID/本文・ユーザー情報はパブリックGitHubへ記載しない。Googleフォルダの権限が「現在の接続ユーザーのみ」とならなければコピー前に中止（共有フォルダ・リンク公開不可）。

**保持期間案**：コピーは検証終了後30日をめどに保持継続/削除をレビューし、独断で削除しない。短期保存を目的とし、原本の唯一のバックアップとして扱わない。**確認前に自動消去・再コピーを行わない**。

**復旧演習案**：第A承認により作ったコピーを読み取り元として、**アプリ未接続の独立メモリ上**で仮復元の等価性を検査する。Google Sheet/Cloudflare D1への実書込復元が必要になれば、さらに別途承認を得る。旧シートを置換せず、既存Worker/GAS/LIFF IDは保持。

**停止条件**：コピーが想定外の外部共有になる、シート構造が不一致、SHA mismatchを修復・書換しなければ先へ進めない、GASの原本が処理中で書込みが混在する等の問題があれば中止。別時点のAPI読取を「原子的スナップショット」と呼ばない。

### 第B承認（A完了後に別途、今は求めない）

会員/LINE識別子・領収書/収支の**本番原本**を独立バックアップする前に、実利用者の個人情報取得同意の範囲/移送先（Cloudflare D1を含む国外取扱や適用ルール）・データ管理責任者・保存期間・領収書複製範囲・復旧責任と、GAS/LINEからの書込みを停止するメンテナンス方式と業務影響を精査する。本番書込停止・原本複製・LINE/Worker接続変更・本番反映は独立した明示承認制。

### リスク・旧仕様への影響評価

- **既存仕様（優先順位1～2）**：全体収支の行順/確定・旧残高、member/duty/admin権限、退会と過去監査、操作ID・試合有効版、GAS/Sheetsが正本。第A承認では一切変更しない。
- **懸念**：架空シートでも個人/操作IDを含み得るバックアップが1件増える。共有・保持・不正アクセスの管理が必要。コピーしただけではGoogle Apps Script紐付け・領収書Drive本体・保護・共有/スクリプトプロパティの継承は保証されない。SHA mismatchの原因は確定しない。
- **代替案**：A（推奨）：架空専用の非共有ネイティブコピーを作成して照合／B：今回はコピーしないで架空メモリテストのみ継続（実移行前の保全ゲートは未達のまま）。本番原本のコピーはどちらにも含めない。

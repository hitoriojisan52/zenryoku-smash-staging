# D1第18工程：架空Google試合版SHAの非破壊追加調査と移送方針の承認境界

作成：2026/11/21。第17工程成功main `a82ed7894be53cccf9be3d86a50e9f6434315224`、[D1第13工程の保全結果](D1_PHASE13_PRIVATE_BACKUP_VERIFICATION.md)、[第10工程のSHA/生成経緯](D1_PHASE10_MATCH_PROVENANCE_BACKUP.md)、[承認済みB/Bの確定仕様](D1_APPROVED_OPERATION_MATCH_ATOMIC_POLICY.md)、現行GAS `matchHash_`/`matchLoad_`/`matchCommit_`を参照。

## 実施範囲と安全性

既にユーザーが承認し第13工程で作成した**非共有Google Sheetsネイティブバックアップ1件だけ**に対し、対象タブの`試合版管理!A1:I20`を読み取り専用で再取得。公開リポジトリに元ファイルID、会員情報、操作ID、試合JSON、個々のSHA値・金額等を出さない。元Google Sheet、コピー、D1、Worker、GAS、LIFF/LINE、業務API、本番への**書込ゼロ**。

現行GASのSHA計算は `Utilities.computeDigest(SHA_256, txt)`、保存時はJSONをUTF-16 30,000 code unit単位で分割し読戻しSHA照合後にreadyにする。したがって、SHA未一致の旧版を**検証完了済みのD1試合版**として無条件に取り込んではならない。

| 項目 | 現役8版の観測 |
|---|---:|
| ready | 8 / 8 |
| 1版1チャンク（index=1, total=1） | 8 / 8 |

**結論**：簡単な空白、改行、JSON表現差を仮定した検査では8件の不一致を解消できない。**原因は依然未確定**。検証中のバックアップは元検証シートと全21タブ/2,641セル一致していたが、元の内容がGASのSHA契約を満たすことは保証されない。第13工程で別途集計したアーカイブ過去版38件も不一致で、全46版は移行No-Goのまま。今回の再検査では**過去38件のSHAを再読取再計算していない**ため、以前の結果を新しい検証成功と誤記しない。

## 次の選択と懸念

**A：推奨 — 既存46版を完全保全したまま、独立した「新規生成の架空試合版」だけでD1の試合保存・復元・削除・会計連携試験を継続する。** メリット：SHA不一致の旧原本を破壊しない、今までのD1技術検証を継続できる。限界：旧46版の移送可能性は未検証のまま。将来の実データ移送のためには元シートの生成経緯/適切なバックアップ/ロスレスの取扱方針を別途決定する。新しい架空値を投入する場合も既存の独立架空D1の**新しい専用テーブル/識別子に限り**、事前・事後の業務20表と既存架空件数の不変照合を行う。元版への上書きは禁止。

**B：以前の不一致が解明するまで試合履歴のD1保存・復元検証を停止し、集金・収支・会員/権限のD1移行候補だけを先行する。** メリット：現行履歴の混入リスクが低い。限界：試合履歴の実運用API切替・全体移行完了を後回しにする。実運用の認証・収支・データ移送はA/Bいずれも独立した承認が必要。

**いずれも行わないこと**：保存済み旧SHA/JSONの再計算値での上書き、差分を黙殺した正本移送、旧GAS/LIFF/公開Worker/原本の変更、本番反映、元データの削除、権限拡大や料金プラン変更。

## その他のNo-Go

- 本番利用者のLINE IDや氏名・領収書・財務情報をCloudflare D1へ移す対象・同意範囲・保持期間・復旧責任の詳細合意。
- GASの本来の残高再計算と収支確定順・操作履歴・最終管理者保護・退会再入会の原子的同値。
- 47業務APIの認証と経路、Read Shadow、本番切替および復旧演習。

**性能改善・LINE連携機能開発はD1移行完了まで引き続き停止**。本番反映は明示承認制。今回の追加調査は読取のみで、A/Bいずれの実装方針にもまだ変更を適用していない。

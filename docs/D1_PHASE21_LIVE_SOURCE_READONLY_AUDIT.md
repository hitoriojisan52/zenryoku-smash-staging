## 権限と証跡の範囲

ユーザーは**B：既存GoogleスプレッドシートのREAD ONLYでの構造・件数・整合性調査**を承認。既存の実データを**変更、複製、移送しない**。個人情報/実ユーザーID・メール・氏名・領収書内容、元の行本文/ハッシュ値/試合JSON、GoogleファイルID/URL/トークンは**公開GitHub・Actionsログへ記録しない**。

- 接続済みGoogle Drive/Sheetsの**メタデータ取得とGETによる値/数式の読み取りのみ**を行った。Google Sheetsへセルの書込・ファイルコピー/エクスポート・共有設定変更は行っていない。個人データは一時的に接続ツールから読み取ってメモリ内で**集計**し、公開先には非識別の表名・総数・リスク分類だけ記録。個人単位の値/ハッシュ/IDは出力しない。
- 同時更新中のシートについて**一貫した原子的スナップショットは未取得**。下記の件数は**調査時点の読取結果**であり、更新が続けば変化する。1つのシートの大きなgrid allocated rowsを実業務レコード数と同一視しない。
- 既存架空D1とWorker・Cloudflare・GAS・LIFF/LINE・既存47 GAS_ONLY API・原本とバックアップ・本番は**一切変更していない**。不一致SHA旧46版への処理・復旧/コピー・再ハッシュ保存を一切行わない。

## 既存D1仕様との差異と停止条件

現在の空D1業務候補スキーマは、第14工程までの架空21タブ由来である。したがって、**現行13シート版から1対1のテーブル名対応/セルの直接移送はできない**。

1. \`practices(practice_id)\` に存在する日程だけが \`attendances(practice_id, participant_id)\` の親になる。73件の過去回答を現在9日程だけで再現することはできない。過去日程を**受付対象外の履歴用として別途記録**するか、**歴史的回答アーカイブとして保存し、現在の参加者一覧APIに混ぜない**かを設計・承認する必要がある。いずれも欠損削除/勝手な受付再開を許さない。
2. フォーム回答のメール＋開催日重複11件は、同一回答の修正なのか、複数の提出なのかが未確認。全原行・原順/タイムスタンプは原本のまま保護し、最新優先や自動統合を未承認で行わない。
3. 数式が出す収支/参加者の値をD1側で同値化するには、GAS実装による権限、収支確定順、集金・料金、残高再計算、退会/再入会を個別検証する。**Spreadsheet formula outputを業務正本の再計算結果として盲信しない**。
4. 旧46版のSHA不一致/会計全計算/操作IDと権限/本当のLINE認証/個人情報・領収書の保存場所と同意・削除/復旧責任/本番切替は引き続きNo-Go。

## 実装・回帰

- \`d1-staging/analysis/phase21-readonly-readiness.mjs\`：**集計済み数値しか受け付けない**fail-closed migration gate。メール/名前/ファイルID/JSON/実明細などの識別フィールド入力は拒否する。照合数が矛盾していた場合も即拒否し、出力は業務上の不明点/No-Go分類のみ。**Google/Cloudflareを読み書きしない**。
- \`tests/check-d1-phase21-readonly-readiness.mjs\`：**完全に架空の人数/日程/数式集計値**だけで、歴史的日程の不在、複合キー重複、数式/旧SHAと正本未選定をNo-Goに固定する。0件であっても「正式移送承認なし」によるブロックを外さない。
- CIは**オフラインだけ**。Google Drive/Cloudflareに認証アクセスせず、PR/検証mainのテスト成功を構造的判断の証拠とし、**実Sheetの再検証完了やD1移送成功と混同しない**。

## 次のユーザー判断地点

- **第一に、D1へ移す業務正本を決定**：A「現行の13シート版を移行対象正本とし、旧3シート版は参照専用」／B「旧3シート版を含む複数台帳を取り込む必要がある」。更新日時やファイル名では決めない。複数を合算すると重複・二重集金の危険があるため、ユーザーの判断なしに統合しない。
- **その後の別判断**：過去73回答の履歴をどう表すか、重複11件をどの時点の確定値と考えるか、D1の本人識別/LINEアカウント対応、同意・保持・復旧の方針。**いずれも原本の修正や既存試合SHAの上書き、本番切替の承認ではない**。
- 原本への追加読取は調査承認の範囲内だが、**複製/移送や書込が必要な段階では必ず停止し改めて許可を得る**。

性能改善・LINE連携開発はD1移行完了まで保留。本番反映はユーザーの明示的な事前承認が必要。

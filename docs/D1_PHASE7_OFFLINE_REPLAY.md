# D1第7工程：架空データによる複数テーブル整合・ロール・監査・ロールバック検証

作成：2026/11/21。対象：検証用リポジトリの**オフラインSQLiteメモリDBのみ**。基準はmainのREADME / SESSION_HANDOFF / SPEC_PRIORITY_POLICY、[第5工程](D1_PHASE5_READ_ROUTING.md)、[所属行原因調査](D1_TEAM_MEMBERSHIP_ROOT_CAUSE.md)、[第6工程日時/監査契約](D1_PHASE6_CIVIL_DATE_CONTRACT.md)。実データのコピー・リモートD1書込・既存API変更を許可しない。

## 保持する既存仕様

- 有効な会員・管理者フラグ優先・当番チームの有効性・所属のactiveによるロール判定。最後の管理者保護。検証専用`stage.selfRole`を本番へ移植しない。
- `operationId`の一意性、再送による重複書込禁止。権限変更と監査は同一トランザクションが必要。退会済み会員の過去の監査行は保持する。
- 日程・出欠・集金・会計・試合の整合、収支残高と先行未確定の順序を保持。**本試験は全機能の業務同値性を証明しない**。
- 旧Sheetsは唯一の正本。47 APIはGAS_ONLY、Cloudflare D1の20業務テーブルは未移行。

## 今回の実装

`tests/check-d1-phase7-offline-replay.py`を追加し、既存の`0001/0002`SQLを**メモリSQLite**に適用、完全な架空の2会員・1日程・出欠・集金・繰越/練習収支・監査を作る。既存第6工程のJST文字列・監査前検査関数を再利用。

| チェック | 期待 |
| --- | --- |
| admin / duty / member、チーム停止 | 管理者優先、チーム停止ならdutyを付与しない |
| 一般へ降格→当番へ昇格 | 同一複合キーをUPDATE/UPSERTし、重複所属行を追加しない |
| 同一operationId再送 | 監査と権限変更を二重適用しない |
| 管理者以外の操作・最後の管理者の降格 | 拒否 |
| 退会済みactorの監査 | 現在のmembers FKなしで履歴を保持 |
| 操作監査ID衝突によるトランザクション失敗 | ロール変更もロールバック |
| 集金・収支を同時に仮変更してrollback | すべての元行が復元され、外部の副作用なし |
| 外部I/OとAPI切替 | なし（Python/SQLiteメモリのみ） |

`.github/workflows/d1-staging-check.yml`に本試験を追加。CIは既存の会計確定順序、出欠、退会再入会、試合生成、D1の47経路禁止と日時変換も引き続き実行。

## 明示的な未実施・移行前ゲート

1. **現実の全20タブ全列のデータ型・数式・行順・参照関係とGASの`getValues()`型の照合**。先の日時234セルと操作履歴210件は限定的な匿名事前監査。
2. 原本のバックアップ・アクセス制御・保存期間・復旧演習と、実データ移転の権限/個人情報の取り扱い。**Sheetsからの無承認コピーは禁止**。
3. 収支確定順序・残高再計算・出欠の本人認証・試合版・退会の多段階更新をGASとD1で比較する実装。今回のSQLite候補ロール関数は**本番用GAS移植ではない**。
4. 実際のD1 Worker/Gatewayへのbinding、read-shadow、切替、同条件のp50/p95測定。データが空のD1を本番APIの読取先にはしない。

読み取り専用の全20タブ列別データ契約とアーカイブ/監査チャンクの復元順を設計する。原本バックアップの安全な経路・権限・復元方法を確立し、**架空データで**GAS同値の書込境界を再現してから、実データの検証用D1投入の是非をユーザーに報告する。ユーザーの事前承認なしに本番へ反映しない。

## 現行GASの復元制約

- **試合版管理**：GAS `matchCommit_` はJS UTF-16 code unit数で1チャンク最大30,000、最大30チャンク。保存時の読戻しSHA-256照合が合格した後に全チャンクを`ready`へ、最後に`試合セッション.activeRevisionId`を切り替える。ロード時はステータス・インデックス・総数・practiceId・SHA-256・JSONを照合する。旧7列の単一行版も読込可能だが、D1スキーマのchunkIndex/total必須制約と差があるため、**旧行を自動補正せず別検証**する。
- **検出限界（重要）**：削除アーカイブには試合版と異なり原文ハッシュ列がない。JSONとして構文正常な文字列内部の書換えは、分割数とJSON構造だけでは検出不可能。原本バックアップ照合・復旧検証・独立した保全方法を実データ移送前に決め、現行アーカイブの完全性を保証したと誤認しない。
- **日程削除／試合削除アーカイブ**：JSONをJS `String.slice`により12,000 UTF-16 code unit単位で分割（最大3,000）。先頭チャンクだけ`prepared`を入れ、アーカイブを先に書き出す。削除処理完了後は先頭だけ`completed`に変更。**preparedや欠番・重複・チャンク数不一致は停止して人による復旧判断**。旧日程削除は収支と参加/試合の他タブも含むため復元は単一表のINSERTでは終わらない。
- **参加者操作／ビジター審査アーカイブ**：JSONは単一行・38,000文字制限、`prepared`の状態を先に永続化。出欠・集金・収支・申請の更新後に`completed`。元JSONを無断変換せず、失敗途中からの復旧手順を別途設計する。
- **共通**：GASが`getValues()`したDate/boolean/数値/文字列を`JSON.stringify`で保存するため、内部の日時の原本表現・行順・元シート値を保持するバックアップの復元性は未証明。D1移行前にGoogle側原本を保護する。
- **会計と権限**：前月繰越・先行未確定の順序・確定済残高、管理者優先・当番所属、最終管理者、退会後旧ID監査、operationId冪等、トランザクションを変えない。

`tests/check-d1-phase8-archives.py` は実データを使わない架空のJSON・UTF-16チャンク・SHA-256について、欠落、重複、総数相違、異なる日程ID、`prepared`、破損ハッシュ、`staging`版を拒否する試験。**本番用の移行・復旧処理ではなく、禁止条件の契約テスト**。

# D1第5工程：接続検証用Google Sheetsの読み取り専用データ移行事前監査

確認日：2026-11-21（JST）。対象：接続検証用v0.15シート（**架空データ**）。実運用の本番Sheetsではない。根拠：[D1_SCHEMA_DESIGN.md](D1_SCHEMA_DESIGN.md)、検証用Spreadsheet ID末尾 `...FBwac`（既存文書に記録済み）、GAS `gas-staging/コード.gs` の `member_` / `scheduleRows_` ほか、直近main。Google Sheets connectorにより**閲覧のみ**で実測した。

## 1. 実施方法／監査の限定

- Google Sheetsメタデータで全21タブ（検証ガイド1＋業務20）、locale `ja_JP`、timeZone `Asia/Tokyo` を確認。
- 業務20タブの**定義済み先頭列**（最大A:P）をそれぞれ実際のグリッド末尾まで `UNFORMATTED_VALUE` で1回ずつ閲覧し、ヘッダーを除く「1つ以上値のある行数」と、設計されたキーの欠落・重複を計数した。**値・氏名・LINE ID・レシート・金銭明細・試合JSONはログ/PRへ出力しない**。
- 検証の対象は指定した列範囲内の現存セルに限る。余分な列、表示形式以外のフィールド、条件付き書式、全数式、手入力とGAS書込の区別までの包括的監査ではない。
- 主キー重複と一部参照整合のみを照合。すべての業務契約・操作履歴・日付型がD1へ安全に移行できると結論しない。
- GitHub ActionsでこのGoogle Sheetsを自動参照するSecret/OAuthは追加せず、**D1 Remoteへ行データを一切書き込まない**。既存D1 20テーブルの構造とビジネス書込先は変更しない。

## 3. 移行阻害要因（原本を変更しない）

### BLOCK-1：チーム所属の複合キー重複（原因判明・移行未実施）

`チーム所属`5行に対し、同じ`(teamId,memberId)`の組み合わせが**1組・3行**存在（有効1行・無効2行）。そのほかの2行は別のキー。

**後続調査で原因を確認済み**：[11/21の実コード・操作履歴の照合](D1_TEAM_MEMBERSHIP_ROOT_CAUSE.md)により、この重複は退会者のデータではなく、11/20に導入した検証専用`stage.selfRole`の操作列 `duty→member→duty→member→duty→admin` が作成したもの。退会時の確定仕様はチーム所属の**物理削除**。3列の残存行に日時・操作者の情報はなく、権限変更の監査は別の`操作履歴`に記録されるため、**この3行を独立した確定業務履歴と見なして専用履歴テーブル追加が必須とした従来の提案は過剰**だった。

現行GASの`member_`は`isAdmin`がTRUEならまずadmin、それ以外は対象会員の有効チームへの所属がTRUEの行を1つでも含むとduty、それ以外はmember。従って現時点の状態だけならD1候補`team_memberships`の`PRIMARY KEY(team_id, member_id)`と**OR(active)による単一行**は一致可能。ただし**元シートの行を直接3行INSERTすると失敗**し、勝手な重複削除・原本修正は行わない。

**暫定候補（未実装・未承認）**：移行時に原本の読取専用スナップショットを保管し、権限の現在値だけをD1の複合キー1行で表現、操作履歴の監査（権限変更時刻・操作者・操作ID）を別に保持。実装では権限変更を冪等な更新と監査書込で再現し、退会時の物理削除・再入会での新IDを維持する。この手順を採用する前にバックアップ・監査整合性・GASとの同値性テストが必要。**実データのD1取り込みはまだ禁止**。

### BLOCK-2：日付セルの物理型が混在

`UNFORMATTED_VALUE` の日付列では、`練習日程` **数値4件＋文字列1件**、`全体収支管理表` **数値7件＋文字列2件**、`操作履歴`の日時 **数値210件**を確認。`get_spreadsheet_cells`で小さく範囲を限定した確認では、それぞれ日付・日時型の書式を持つ数値セルがあった。日付列3箇所の部分確認で`formulaValue`は0件（**全タブ／全数式ゼロの証明ではない**）。

D1の`practice_date`、`ledger_date`、`timestamp_raw`はTEXT設計。Google日付シリアル値と文字列をJST基準で可逆に正規化する方法、`HH:mm`の時刻と生ログ日時の保持方法を確定し、日付境界と繰越/報告時刻のfixtureを合格させるまで**実データ変換は禁止**。

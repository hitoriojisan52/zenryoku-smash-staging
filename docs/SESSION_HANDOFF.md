## 3. 特に守る確定業務仕様と回帰テスト

### 3.1 全体収支管理表（重要）

- **古い収支行から順に確定する。過去・先行する未確定行が1行でもあれば、後続の「確定」は非活性。**
- 判定対象は表示中の月だけではなく**全収支行**。前月以前も含み、同じ日付は既存の残高計算順（日付→種類→固定ID）に従う。
- フロントのボタン活性制御だけでなく、**GASの確定APIでもScriptLock内で同じ順序を強制する**。直接API呼び出し・古いブラウザ・複数端末からの確定も拒否する。
- 「全体収支管理表」と「集金ホーム」の両方で確定の資格を共有。先行行を確定したら再取得で後続行が活性化。未来日・確定済み行は確定不可。
- v15参照の外観：**横長の表／先月繰越行は淡黄色／操作は左寄せ／修正・削除・確定ボタンの配置枠を維持**。練習日行などの修正が不要でもボタンを消さず非活性にする。確定済みは変更・削除不可、管理者のみ確定解除。
- 金銭計算：`残金 = 前行残金 + 集金額 - 支出`、確定済み残金の整合性を壊す過去行操作は拒否。未確定行の修正・削除は保護された再計算を用いる。
- 金種の現金確認は集金や帳簿残高を書き換えない。二重送信、操作履歴、参加者ID、権限の検証を維持。
- 練習日程の確定で対応する収支行を作成。**将来月・未来日も未確定行として表示してよい（2026/11/19ユーザー承認A）。ただし未来日確定・集金は禁止。**「その他の収支」区分も承認済み（B）。
- 自動試験：`tests/check-stage-ledger-confirm-order-v1651.cjs`。前月未確定・同日順序・先行確定後の活性化・未来日・拒否時書込ゼロを検証。既存の集金・残高・旧v15レイアウトのテストも必須。

### 3.2 画面・権限・退会

- **UI共通A**：初期表示・手動更新・保存中は全画面ロック。自動更新時は全画面ロックしない。誤操作防止、確認メッセージ簡潔、実機スマホの操作性重視。
- 画面レベルの閉じるは右上。入力・確認・エラーポップアップに新たな右上閉じるボタンを追加しない。キャンセル／保存／危険操作は従来の下部配置。
- メンバー権限管理：利用者一覧を参加者カード形式とする。「有効」の冗長表示なし。最後の管理者と管理者本人の権限プルダウンと行内変更ボタンは、役割を表示したまま非活性。
- 退会履歴：折りたたみの「退会履歴を見る」。履歴0件で「退会履歴はありません。」。履歴API未対応は非表示。簡素な氏名・状態・退会日時（**記録がある場合だけ**）の行。
- **退会・再入会は過去に確定済み**（[v0.16.53正式引継ぎ](stage-v1653-withdraw-rejoin.md)）。退会時にメンバー登録とLINE ID紐付け、チーム所属、旧登録申請を削除し、閲覧リンクは失効。過去の出欠・集金・収支・試合・監査を維持。再入会は同じLINE IDで申請し、新memberId・一般メンバーとして承認。退会中`processing`時はアクセス停止・自動再送禁止。
- 現行GASの権限・本人確認を必ず保持。UIのdisabledだけでは安全制御とみなさない。

> **2026/11/19 v0.16.56の確認済み変更**：[メンバー権限・収支操作の仕様差分](stage-v1656-management-ledger-ui.md)を参照。メンバーカードは上部右側に権限選択、下に修正・権限変更・退会の３ボタン（不可でも非活性表示）。退会確認は１回、退会ボタン赤、退会履歴は氏名左／退会日右の１行。氏名修正は管理者が実施し、会員マスタと一意の承認済み申請だけを変更（過去の出欠/集金/収支/試合履歴は不変）。収支未確定行の修正・赤い削除・確定の３枠とv15の確定順序を保持し、**確定済みは当番担当「確定済み（非活性）」のみ、管理者「確定解除」のみ**。ただし今回のWorker/GAS/Pages実反映はCIと別途確認する。

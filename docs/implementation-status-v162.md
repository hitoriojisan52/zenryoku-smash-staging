# v0.16.2 権限別画面 / 段階移行メモ

## 実装済み（GitHub main / 検証用）
- 対戦表の操作領域 `matchControls` は `admin` または `duty` のときだけ表示。一般メンバーは対戦表閲覧、開催日選択、更新、閲覧QR発行のみ。
- `match.js` の `mutation()`, `change()`, `draftEdit()` にクライアント側権限ガードを追加。
- GAS v0.16 の `matchApiDispatch_()` は `match.get` と `match.practices` の読み取り以外について `requireDuty_()` を適用。権限の最終判断はGAS側で実施。
- `live.html` に管理者用「メンバー・権限管理」ダイアログを準備。UIは `live-access.js` に分離。メンバー申請の承認・却下、3権限の変更でv0.16の既存APIを使う。
- 管理者以外は運用管理画面の「メンバー・権限管理」「練習日程」を非表示。練習日程管理自体はまだ未接続のため管理者でも利用できない。
- 運用管理用LIFFで管理者画面を実機確認済み。`match.html` の暫定管理画面を撤去し、承認・権限変更を`live.html`へ集約済み。

## リッチメニューの予定仕様
- 未登録：新規登録（現行対戦表LIFF IDを利用できる。未登録時は登録申請フォーム）
- 一般メンバー：参加連絡・予定修正／日程確認／参加者一覧閲覧／対戦表
- 当番担当・管理者：一般メンバーの4項目＋運用管理ツール
- 権限変更時にMessaging APIのユーザー単位リッチメニューを変更する。既存LINE Official Account Managerのデフォルトメニューは本番移行まで維持する。
- LINE公式ドキュメント：https://developers.line.biz/ja/docs/messaging-api/use-per-user-rich-menus/
- 実装時に必要：各リッチメニュー画像、LINE Messaging APIチャネルアクセストークン（Worker側Secret）、リッチメニューID（非秘密）、アカウントの友だち登録状態。承認成功後のLINE APIエラーは失敗キューに記録して再同期する。
- URLやトークンを公開GitHubに保管しない。リッチメニューの見せ分けだけを権限制御とみなさず、GAS API側の許可判定を必須とする。

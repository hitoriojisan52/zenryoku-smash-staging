# 全力☆スマッシュ 旧運用管理ツールv7：画面・操作の継承基準

基準：利用者が過去のチャットで提供した **`最終調整版_v7_Index.html`**（全1,947行）と、2026-11-16の`zenryoku_smash_integrated_design_stage7.md`および後日確定した共通UI仕様。2026-11-18の利用者指示：**内部データモデル/APIは再構築するが、未実装の運用管理機能は旧画面の見た目と操作を踏襲すること**。

## 継承の適用範囲・優先順位
1. **画面仕様**：旧v7のメニュー名、操作項目、表示順、金種、＋/−操作、確認ポップアップ、ボタン名、結果表示を基本として忠実に引き継ぐ。新たな操作方式へ勝手に変更しない。
2. **共通画面ルール**：後日確定した配色・可読性・モーダル・トースト・操作ロックを優先。初回/手動再読込/保存は全画面ロック、自動更新は操作禁止にしない。集金チェックの並行保存に関する個別確定ルールは維持。
3. **内部処理**：新しい固定参加ID、版番号、排他ロック、権限、操作IDによる冪等性、分離スプレッドシート/APIを使う。旧シートの物理行番号や日付だけを更新キーにしない。収支の二重計上・既存確定行変更を禁止。
4. 旧v7と新業務ルールが矛盾する場合、**利用者の後日確定事項**を優先。UI上の差分はテスト前に説明し、未実装を完成扱いしない。本番は個別承認制。

## 1. メイン・運用ツール
- 旧v7のホーム：集金チェック、参加区分の長押し、集金額・当日補正・支出・残金など。集金画面の新規参加者登録ボタンは設けない（LINE参加連絡が入口）。
- 旧v7は上部「📂 運用」「⚙ 管理」。運用ツール内は横並びの **💰 現金確認 / 🧾 領収書 / 📊 収支表** タブ。
- 新LIFFで既に確定した「💴 立替精算」「⚙ 運用管理」等の外側の配置を優先し、未実装機能の**内容と操作**を旧v7へ寄せる。ナビゲーション全体を不用意に巻き戻さない。

## 2. 現金確認（旧v7の該当ソース：L295–326、L1737–1934）
- 選択中のホームの開催日が **参照日付**。新しい独立日付選択欄は設けない。
- 上部サマリー：**参照日付 / 帳簿残高 / 実査合計 / 差額**。
- 金種は**9種類のみ**、順番は「1万円札、5千円札、千円札、500円玉、100円玉、50円玉、10円玉、5円玉、1円玉」。**2千円札は旧v7にないため追加しない**。
- それぞれ **「−」・枚数・「＋」・金種別小計**。初期枚数は0、マイナスにはできない。
- 差額：`0円 (一致！)`、`+○円 (超過)`、`−○円 (不足)`。対象日の収支行がないときは警告と保存非活性。
- 下部アクション：「**枚数をリセット**」→「枚数をすべてリセットしますか？」→「いいえ / リセットする」。「**現金確認**」→「○年○月○日の金種枚数データを保存しますか？」→「キャンセル / 保存する」。
- 再表示で保存済み枚数を再取得して表示する。成功は短時間トースト。
- **旧v7は金種枚数の保存がある**。2026-11-18のv0.16.37a「入力は保存しない・10種類・数値入力・独立日付選択」は旧v7と異なるため、**完成版とはみなさずv0.16.37bで是正**。
- 新内部構成では現金確認を**`現金確認記録`独立シート**に保存する。全体収支管理表の残金・集金額・支出は変更しない。旧v7の操作を保ちつつ新設計の「金種は収支表の6列へ持たない」も守る。

## 3. 管理ツール：練習日程マスタ
- 旧v7の管理画面の第一タブ：「📅 練習日程マスタ」。
- 画面上部：「**＋ 日程追加**」「**🔄 フォーム更新**」。日程カードに開催日/時間帯/時間数/会場/備考、`✔ シート作成済` または `⏳ 未作成` の状態表示。
- 未作成の日程は「修正」「削除」「確定」、作成済みは修正・削除が非活性。
- 編集フォーム：開催日（yyyy/MM/dd）、時間帯（例9:00-13:00）、時間数（2/3/4）、開催場所プルダウン、備考（任意）。
- 旧v7の会場選択肢：曽谷公民館／北方小学校／勤労福祉センター／信篤市民体育館／塩浜市民体育館／東部公民館。これらはあくまで旧ソースの初期選択肢。
- 削除時：「【日程の削除】」「キャンセル / 削除する」。確定時：「【参加者一覧シート作成の確定】」「キャンセル / 確定して作成」。フォーム更新時も確認ポップアップ。
- **新内部構成の注意**：新シートは日付別参加者シートを作らない構造。旧操作「確定」「フォーム更新」を、新しい練習日程・受付有効化処理へどう対応付けるか慎重に検証し、旧シートを新規大量作成しない。表示文言が実処理と食い違う場合は利用者確定を待ってからデプロイする。

## 4. 管理ツール：参加者一覧
- 旧v7の第二タブ：「👥 参加者一覧」。開催日選択、更新、追加（旧Googleフォームへのリンク）。
- 出欠回答カードは「👤 氏名／区分、参加or欠席、📧メールアドレス、📅登録日時、📝備考（任意）」、右下に「修正」「削除」。
- 修正画面：お名前、メールアドレス、出欠（参加/欠席）、区分（メンバー/ビジター/学生/当番担当/シャトル担当）、備考。「キャンセル / 保存する」。
- 削除時：「【回答の削除】」「○○さんの回答行を本当に削除しますか？」「キャンセル / 削除する」。
- **新内部構成の注意**：旧フォーム回答の物理行番号を使わず参加IDを使う。一般会員の出欠変更・代理ビジター登録、LINE連絡と収支/試合の参照整合性を守る。旧フォームのメール・登録日時の項目は、新システムで収集/保存する設計を確認するまで空欄の扱いを勝手に決めない。

## 5. 領収書・収支表
- 旧v7運用タブの「領収書」はフォームへの導線。「収支表」は全体収支表と「＋ 立替精算」。
- 現行の新UIで既に確定した収支表の月別6列・繰越・未確定操作・管理者確定解除・立替精算のフォームは後日確定仕様を優先する。重複精算・領収書二重計上は不可。
- 任意領収書の実アップロード等は、旧HTMLの外部フォームリンクがあるだけで**新APIは完成していない**。完成扱いしない。

## 6. 受入手順
- 旧v7に対応する各タブ・入力・ボタン・確認ポップアップと1対1の項目照合表を作り、自動回帰テストへ組み込む。
- 未実装の操作を無言で別方式に置き換えず、差異が残る場合は既存ボタンを非活性にし、状況を明示する。
- ステージングの架空データで正常/異常/権限/競合/再読み込みを確認。本番環境は明示的な承認まで変更禁止。

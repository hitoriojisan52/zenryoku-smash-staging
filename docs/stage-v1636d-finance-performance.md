# v0.16.36d 集金保存の低遅延化 — 接続ステージング

日付: 2026-11-18。**本番および別の退会検証環境へ適用禁止**。

## 既知の実測値
利用者のLINE診断URL `?accessUi=v2&perf=1&v=1636c` で連続3回の集金操作が成功。
- 全通信: 3.9、4.4、3.7秒（平均4.0秒）
- Worker `Server-Timing` のGAS区間: 3.7、4.3、3.6秒（平均約3.9秒）
- LINE検証区間: いずれも画面上0.0秒（小数第1位に丸め）
- 以前の6～8秒より短縮。ただし大半はGAS区間のため、現状は高速と評価しない。

## 今回のソース変更
- `gas-staging/コード.gs`：
  - `setPayment_` の既存の `balanceRecalc_(rows,original)`、確定済み残金の不変条件、集金行のバージョン検査、操作ID重複防止、スクリプトロックは維持。
  - 従来の `writeLedger_` は、集金チェックごとに全16列×全収支行を上書きしていた。
  - 検証済みで、収支表の物理行数と論理行順が一致し、対象練習行の `income` / `balance` / `version` しか変わらない場合のみ、**収支表の当該行C:K（9列）の1回書き込み**に変更。
  - 将来日程・他行の残金が変わる、行順が違う、空行や不明行がある、他の列が変わるなどの場合は従来の**全件書き込みへ安全側フォールバック**。読み取りを省略したりロックを外したりはしない。
- `live.js`：診断用URLの保存結果に、既存の通信/LINE/GAS合計に加えて `GAS POST` と `応答GET` の時間を表示。通常モードは変更しない。
- `live.html`：診断画面のスクリプトを `?v=1636d` としてキャッシュ更新。
- `tests/check-gas-payment-fastpath.cjs`：一行更新、OFF戻し、将来行、行順違い、途中空行、他の列変更の各フォールバックを実行検証。
- 自動/手動GitHub ActionsのGASデプロイ前に、追加の低遅延テストを実行する。

## 注意
今回の書き込み範囲削減は**実測した高速化を保証しない**。GASの3.6～4.3秒にはApps Script起動・SpreadsheetApp・GoogleのContentServiceリダイレクト取得が含まれる。Workerの `gas_post` / `gas_content` に分けて測定し、どちらが主因かを次回確認する。

GitHub上の変更をマージしてもGAS自動デプロイはOFFのまま。**初回から使っているGitHub Actionsの手動 `mode=deploy` を実行するまでは、GAS v0.16.36dは現行デプロイには適用されない**。事前に `mode=preflight` 合格を確認し、更新後はユーザーの合意した架空参加者のみでON/OFFを1回ずつ検証。連打・本番操作はしない。

実行前後に、ステージングの `全体収支管理表`、`集金記録`、`操作履歴` を確認する。別名のバックアップに誤って書き込まない。

## 追加する診断情報
対象: `payment.set` のうち `profileTimings:true` が送信された認証済みリクエストのみ。
既存の `Server-Timing` と `GAS POST/GET` は維持。

GASが計測する値（ミリ秒）:
- `spreadsheetOpenMs`: スプレッドシートOpen
- `memberAuthMs`: LINEユーザーと会員の紐づけ確認
- `lockWaitMs`: スクリプトロック取得
- `auditReadMs`: 操作ID重複照合
- `practiceReadMs`: 練習日程検索
- `ledgerReadMs`: 収支行読み込み
- `attendeeReadMs`: 出欠回答読み込み
- `paymentReadMs`: 集金記録読み込み
- `validationMs`: 料金・収支の整合性計算
- `paymentWriteMs`: 集金記録保存
- `ledgerWriteMs`: 収支表保存
- `auditWriteMs`: 操作履歴保存
- `handlerMs`: GASハンドラ総所要時間（ContentService転送等は含まない）

GAS側の既存処理は一切省略せず、`Date.now()`だけを追加。診断値にID・氏名・トークン・シート内容は含めない。操作履歴へ診断値を保存せず、成功レスポンスのみに付加する。
標準モードでは送信フラグがfalseのため詳細計測しない。

## 検証と運用
- GitHub PRの安全チェック合格後に`main`へマージ。既存の自動GASデプロイが起動。
- GitHub ActionsのGAS更新・ソース照合を確認し、Sheetの集金状態を読み戻す。
- ユーザーへはLINEから**1名の架空参加者をON→OFF**のみ依頼。二重タップ不可。実行後、トーストおよび詳細欄の秒数/msを報告してもらう。
- データ不整合・応答不明時は連続再実行せずログ照合。実測した内部ボトルネックの箇所だけを次の版で最適化する。
- 本番環境のデプロイは引き続きユーザーの明示的承認が必要。

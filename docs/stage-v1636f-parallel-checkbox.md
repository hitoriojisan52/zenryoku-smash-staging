# v0.16.36f 接続ステージング・集金チェックボックス並列操作

2026-11-18。接続ステージング（架空参加者）のみ。**本番環境へは展開しない。**

## 目的・UI仕様
- 現状 `cb.change => guard(...)` が全画面 `SMStageUX.run` を使っており、保存中に他のチェックボックスを触れない。
- 新仕様：**集金チェックに限り**共通全画面ロックを使わず、タップした本人のチェックボックスだけを無効化。「保存中…」または「順番待ち…」を表示し、他の参加者のチェックは続けて受け付ける。
- 同じ参加者の連打・二重送信は不可。異なる参加者は最大2件を同時リクエスト開始、3件目以降はそのチェックだけ順番待ち。
- 他の金融変更（開催日切替、収支確定、金額編集、運用管理）は保存中に禁止。初回読込・手動保存など、集金チェック以外の共通UIロックは変更しない。
- GASの `LockService.getScriptLock()` は変更しない。**複数のHTTP通信を同時に受け付けても、GASの収支計算・書き込みは直列化**される。処理総時間短縮の保証ではなく、操作待ちを減らす機能。
- 背景の8秒間隔自動更新は、保存中・待機中・保存結果未確定の間は開始しない。すでに発行済みの古い読込応答も既存 `updateEpoch` で無視する。

## 金額の保護
- 送信時、ユーザーID・開催日・支払前バージョン・操作UUID・ON/OFFを一回だけ生成して保持する。
- GASの本人確認、参加者確認、支払バージョン検証、ロック、収支再計算、確定済み行の保護、履歴への冪等記録をすべて維持。
- 2件の保存成功が逆順に返る場合、`ledgerVersion` が大きい確定レスポンスだけが全体残高を更新。個人の完了状態・バージョンは本人ごとに更新する。
- サーバーで明確に拒否された操作と**未送信の待ち行列**だけチェックを元に戻す。通信が不明な処理はサーバーで実行済みの可能性があるため自動再送・軽率なロールバックをしない。
- ひとつでもエラーになったら、送信前の待機操作は中止。処理中の別件が終了した後に**手動「更新」**で状態を照合。結果が確かめられるまで新規集金操作を受け付けない。

# v0.16.36g 集金並行操作の失敗時安全対策（検証環境限定）

2026-11-18。v0.16.36f をベースに、架空参加者を使う接続ステージングのみ変更する。本番環境には配布しない。

## 修正した2点

1. **HTTP 200 でも応答の内容が不正な場合**：従来は待機キューの通信枠を解放した後に応答内容を照合していたため、結果の不整合が分かる前に3件目の送信が始まり得た。応答の練習ID・参加者ID・完了状態・個人バージョン・収支バージョン・金額をキュー実行中に照合し、失敗を通知して未送信キューをキャンセルしてから通信枠を空ける。
2. **失敗後の未操作チェックボックス**：以前はエラーになった本人のチェックだけが無効になり、他人のチェックが押せるように見えることがあった。エラー後は全員の集金チェックを無効にし、保存中のほかの操作が終わってから手動「更新」で整合性を確認した場合だけ再有効化する。

通常の保存中は選択した行のみ無効になり、異なる参加者は最大2件同時に通信する仕様を維持する。GASの排他制御、冪等操作ID、会員・権限検証、収支計算は変更しない。サーバーで保存された可能性のある不正応答は自動再送・自動ロールバックせず、手動更新で実データを照合する。

## テスト

`tests/check-stage-payment-parallel-v1636f.cjs` に以下を追加する。

- 3件選択中でも未操作の4人目は有効のまま（通常の並行操作）。
- 409競合時に未操作のチェックも無効化し、手動更新成功相当の状態で有効に戻る。
- 200応答で別の参加者IDが返った場合、待機中の3件目を決して送信せず、確定済みの可能性がある1件目は勝手に巻き戻さない。
- エラー中に処理されていた2件目が成功した場合、その結果は反映し、送信していない3件目のみロールバックする。

PRのCIとGitHub Pagesの反映を確認してから、LINEの実機操作で正常系3人ON→OFFとエラー後の再読込を確認する。実機の確認が取れるまでは最終合格としない。

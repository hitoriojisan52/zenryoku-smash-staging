# v0.16.37c: 現金確認の再表示で誤って409が発生する問題

発生報告：2026-11-18。操作順は「現金確認を保存→集金ホームでチェックボックス操作→現金確認を再表示」。ポップアップ「内容が変わりました／ほかの人が先に変更しました」が出た。

## 原因：日付型の自動変換
検証用シート`現金確認記録`のB2（`auditDate`）を読み取り検査したところ、表示は`2026-11-16`である一方、Google Sheets の保存型は `numberValue` かつセル書式 `DATE`（Sheets内部日付シリアル値）だった。Apps Scriptの`getValues()`では`Date`オブジェクトとして返る。

v0.16.37b の現金確認APIでは`str_(saved[1])!==p.date` と直接比較していた。`Date`の文字列化は`yyyy-MM-dd`ではないため、**実際は同じ開催日なのにCONFLICTを返す**。現金確認の保存後に再読込するだけでも発生し得る。集金チェックの実行は直接原因ではない。

## 修正
GAS `cashGet_`（取得）と `cashSave_`（更新）の旧式日付比較を、既存の収支処理で採用済みの`ledgerDate_`（JSTでyyyy-MM-ddへ正規化）に置換する。

- 保存済みデータの日時・金種・金額を一切書き換えず、Date型と文字列型のどちらも正しい日付として扱う。
- 異なる日付なら従来どおりCONFLICTを返す。
- 役割認証・ScriptLock・バージョン競合・操作ID・金種9種・保存確認・収支から独立した会計記録は維持。
- GASのみ変更。Worker、GitHub Pagesの画面/URL、既存スプレッドシート、確定済み収支には変更なし。

## 回帰テスト
`tests/check-stage-cash-reconcile-v1637.cjs`に、Sheetsで実際に発生した`DATE`の型変換を模した`Date`保存データを投入。現金確認の初回保存・開き直し・再保存、集金による帳簿残金変更後の現金確認再表示、残高差額の更新、および**異なる日付の拒否**を検証。

既存のGAS/Worker/共通UIの回帰テストを必須とし、合格後のみ検証GASの既存デプロイを更新。本番への変更は禁止。

## 実機確認
1. これまでと同じLIFFを開く（画面URL変更なし）。ホームで2026/11/16を選択。
2. 運用管理→現金確認を開き、保存済み金種（検証シート上は1万円札1枚・5千円札2枚）が読み込まれること。
3. 集金チェックのON/OFF後、もう一度現金確認を開く。競合のダイアログが出ず、**最新の帳簿残金と保存済み金種から計算した差額**が出ること。
4. 今回は再保存は必須ではない（既存データ保護）。もし現金確認の保存を試す場合は、変更後に再読込した最新の版番号で行う。

# v0.16.38b 検証版 — 練習日程マスタUI・時間区分・ビジター代理登録

作成：2026-11-18。対象は検証用LIFF／GitHub Pages／Worker／GASのみ。本番環境は明示承認まで変更禁止。

## 利用者の今回の確定事項

- 練習日程マスタの一覧は**本日を含む未来**（`date >= Asia/Tokyoのtoday`）。過去日を除外する。
- 日程追加ボタンは「📅 練習日程マスタ」と**同じタイトル行の右側**に配置。幅は文字量に合わせてコンパクト、タップ領域は維持。
- 旧Googleフォーム更新ボタン、旧説明文「確定すると新システムの日程一覧に～」を**削除**する。
- 開催日はスマホのネイティブカレンダーで選択。`yyyy/MM/dd(曜日)`を入力欄の直下と一覧に明記し、入力例文を廃止。
- `hours`の実体は参加費の計算に使用する **「時間区分」**（2/3/4）。開始・終了時刻の差分と一致させない。例：9:00～11:30（実2.5時間）でも時間区分3を認める。料金計算はこれまでの `fee_(category,hours)` を維持。
- 備考は空の状態。旧`部内戦候補日 など`というプレースホルダーを削除。
- ビジターの参加登録はGoogleフォーム不要で、**アプリ内**から実行可能にする。

## ビジター登録の画面・認可

- 当番・管理者：運用管理メニューの「＋ ビジター登録」から登録。未完成の従来「参加者管理」ボタンは引き続き無効。
- 一般メンバー：同じLIFFのLINE認証後、集金管理を見せず**ビジター登録専用の入口**を表示。旧業務ルール（LINE登録したメンバーがビジターを代理登録）の権限を守る。
- カレンダーではなく当日以降の**受付公開済み**開催日一覧を使用。日程選択、名前、氏名カナ（任意）、備考（任意）、確認ポップアップ「登録する」。
- ビジター本人のLINE認証・メール入力は不要。登録者IDはAPIで認証したメンバーのIDをサーバー側から取得し、クライアントによる任意指定を採用しない。
- `出欠回答`に現在の9列構造のまま`practiceId, participantId(PV-UUID), displayName, nameKana, category=visitor, attending=true, remark, version=0, registeredBy`を保存。既存の参加者一覧・集金／対戦表が同一固定IDを参照。**同姓同名でも別IDにする**（自動マージしない）。
- APIはWorker経由 `/api/visitor/practices`（読取）、`/api/visitor/register`（登録）。一般メンバーもLINE本人確認必須。登録はGASの ScriptLock、operationId監査・冪等性を維持。
- 公開前・過去日の登録、確定済み収支の対象日への新規登録、二重利用の参加者ID、不正な名前は拒否。既存の集金額／支出／帳簿残金、開催日程、対戦ラウンドを**書き換えない**。
- 通信で登録結果が分からないときは自動再送しない。画面内の再登録を止め、確認を促す。

## UIの変更箇所

- `live.html`／`live.js`：新カレンダー、曜日補助表示、時間区分表記、追加ボタン移動、フォーム導線削除、ビジター代理登録ダイアログ、一般メンバー専用表示。
- `gas-staging/コード.gs`：時間区分と実時間の一致制約を解除し、終了時刻が開始時刻より後か検証。既存の`hours`列は変更しない。ビジター登録のAPI二つ。
- `cloudflare-worker/worker.js`：認証付きAPIルート2つのみ追加。
- スプレッドシート**列の追加・既存データ変更なし**。旧v7の画面を尊重しつつ、現行9列の固定IDを利用。
- 日程確定後の日付別シート作成は行わない。

## 実機テスト

1. `https://liff.line.me/2012602642-XBSkXduO?accessUi=v2&v=1638b` を開く。「運用管理 → 練習日程」へ。
2. 日程追加ボタンがタイトル右側で小さく表示、フォーム更新・長い説明なし。本日の日程もあれば一覧に表示。
3. 日程追加 → カレンダーで未来日選択、曜日が表示。9:00-11:30、時間区分3、備考空欄で保存できる。
4. 「確定」を実行して受付対象にする（確定済みは修正・削除不可）。
5. 運用管理 → ＋ビジター登録で公開日程を選び、氏名・必要ならカナ/備考を入力、確認して登録。集金チェックは未完了で追加され、料金は**時間区分3**のビジター料金。
6. LINEで登録済みの一般メンバーから同じ検証用LIFFを開くと、現金・集金データを表示せずビジター登録だけ利用できる。
7. 既存の収支残金／集金額／現金確認枚数／対戦表の生成済み組合せが勝手に変わらないこと。

※ 一般メンバーのLINE側に新しいリッチメニューを配置する操作は今回含めない。URLでのアプリ内登録を先行し、LINE参加連絡との一元化は別工程で行う。

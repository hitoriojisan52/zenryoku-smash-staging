# v0.16.38e — 集金管理手動更新スピナー・参加者一覧500エラー修正

対象：検証用GASとGitHub Pagesのみ。2026-11-18。Workerのルーティング、API認証、収支・出欠・集金・試合データ、本番環境は変更しない。

## 不具合1：👥 参加者一覧のサーバーエラー
### 再現
運用管理 → 参加者一覧。画面には「操作できませんでした／サーバー側で処理できませんでした」と表示される。

### 原因
`participantMatchLocked_`が`sheetRows_(ss,'試合セッション')`を使用。汎用`sheetRows_`は`SM.headers[name].length`を参照するが、`試合セッション`は別の試合エンジンが管理する専用スキーマであり、`SM.headers`へ登録されていない。したがって`TypeError`が発生し、GAS処理が失敗する。

### 修正
`sheet_(ss,'試合セッション')`により正しい既存シートを直接参照し、実データの開催IDが入ったA列だけを`getRange(2,1,last-1,1)`で照合する。ヘッダーだけのシートでは`getRange`を呼ばず`false`とする。関連する対戦表の改変禁止ルールは維持。既存参加者16件、集金13件の読み出し・書き換えは本修正では行わない。

## 不具合2：集金画面の更新スピナーが表示されない
### 再現
集金管理ホームで「更新」を押す。状況によって全画面スピナーを表示せず、更新が即終了する。

### 原因
8秒ごとの自動読取が進行中は`S.loading=true`。`guard(()=>reload(true))`のUIロックは開始されるが、`reload`は冒頭で即returnするため、同じイベントフレーム中にビジーダイアログが閉じてスピナーが描画されない。さらにユーザーが要求した手動更新も処理されない。

### 修正
- `S.reloadPromise`で自動・手動双方の現在の読取を追跡する。
- 手動更新は自動読取中なら完了を待ち、**必ず新しいデータをもう一度取得して日程プルダウンを更新**する（`refreshDates=true`）。
- 受動的な8秒自動更新では画面操作をロックしない。
- 手動更新では既存の`SMStageUX.run`（全画面ロック／共通スピナー）を使用し、`requestAnimationFrame`で描画フレームを確保してから読取処理を開始する。
- エラー後も`S.loading`／`reloadPromise`を解除して次の手動更新を受け付ける。
- 集金チェックボックスの独立非同期保存・収支計算・版番号は維持。

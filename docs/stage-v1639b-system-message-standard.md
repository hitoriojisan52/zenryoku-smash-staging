# v0.16.39b｜システムメッセージ共通表示仕様・全機能横断（検証用）

日付：2026-11-18。対象：接続検証用 GitHub Pages の運用管理・対戦表・対戦表閲覧・ビジターQR閲覧画面。

## 共通仕様
- **画面内に常時表示すべき、操作不能理由・登録なし・受付状況・処理条件等**は、共通クラス `stage-system-message` を使用する。
- 場所は原因となるコンテンツの直近（操作ボタン・一覧・集金欄の付近）。左右揃え、文字の折り返し、余白、枠線、角丸、文字サイズ13px、行間1.55を共通化。狭いスマホ画面でも1行に切り詰めない。
- **警告（黄色）** `stage-system-message--warning`：集金不可（開催日前／前日程の収支未確定）、参加者不足で対戦表作成不可、対戦表作成済みで参加者編集不可、確定済みで編集不可、受付日程なし、現金差額／帳簿未取得の注意。
- **通常の案内／空データ（青系）** `stage-system-message--info`：対戦表未作成の閲覧案内、参加者0件、練習日程0件、メンバー登録申請中・処理状況、メンバー管理の検証状況、読み込み中。
- **画面内エラー（淡赤色）** `stage-system-message--error`：閲覧専用対戦表の取得失敗、ビジターQR閲覧失敗。一般的な更新／登録操作エラーは既存のエラーポップアップへ送る。
- どの画面も`role="status"`＋`aria-live="polite"`を優先し、`hidden`または空の要素は表示しない。参加者名・エラーテキストを`textContent`経由で表示する。
- **区別して維持するUI**：試合の進行状態見出し（「第n試合」「開始前」など）、保存完了の一時的トースト、入力ラベル、実データの集計・料金。確認ポップアップ（標準タイトル／キャンセル＋実行）とエラーポップアップ（赤タイトル／赤い上線／閉じるのみ）は意図的な別仕様。読み込み・保存時の全画面スピナーと自動更新の操作禁止ルールは維持。

## 対象の横断適用
| モジュール | 対象メッセージ／要素 |
|---|---|
| 集金管理 `live.html` | `collectionLockReason`（警告） |
| 現金確認 | `cashStatus`（読込中は案内、未作成・帳簿変更は警告。長文も折り返す） |
| 練習日程マスタ | 予定なし `scheduleList` 空データ（案内） |
| 参加者一覧 | `participantNotice`（編集不可理由は警告）、回答0件（案内） |
| ビジター登録（既存暫定） | `visitorStatus`（受付対象なし警告） |
| メンバー・権限管理 | `memberAccessStatus`、検証ステータス（案内） |
| 対戦表進行／参加者・固定ペア設定 | `matchBody`：参加者不足は警告／対戦表未作成は案内 |
| 対戦表閲覧（一般メンバー） | 対戦表未作成は案内／読取エラーはエラー |
| QR閲覧（ビジター） | 対戦表未作成は案内／閲覧リンク・通信エラーはエラー |
| 登録申請／QR発行 | `accessMessage`（案内・警告・エラー） |

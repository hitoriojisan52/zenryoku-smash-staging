# v0.16.42 — ビジター申請カード統一／日付選択／折りたたみ／本人修正

2026-11-18。**検証環境のみ**、本番には反映しない。既存シート列は変更しない。

## 全画面共通の参加者カード
- **参加者一覧**：氏名・区分・出欠を上部に表示。メールアドレス（メンバーのみ）／登録日時／備考を左側、修正・削除ボタンを**同じ内容行の右下**に配置。備考が空でも位置は維持し、ビジターを含む全区分に適用する。
- **ビジター登録（自分の申請）**・**ビジター管理（管理者）**：同じカード構造・色と余白、氏名・区分・出欠／日時・備考・ボタン右下を採用。ビジターにメールアドレスは存在しないため、カードにもフォームにも表示しない。
- 「承認待ち／承認済み／却下済み」ステータスバッジは**申請者のビジター登録画面のみ**に表示する。管理者は承認／却下ボタンの状態で審査可能状態を判別できる。
- 両ビジター画面に開催日のプルダウンを設け、申請がある日程でフィルタリングする。「すべての日程」に戻せる。
- 「＋ 新しいビジターを申請」フォームは `<details id="visitorNewFormSection">` とし、初期状態は折りたたみ。申請状況はフォームの**上側**に維持する。申請成功後はフォームを閉じ、ステータス一覧を更新する。

## ビジター登録画面の「修正」「削除」ボタン
| 状態 | 修正 | 削除 | 管理者承認／却下 |
|---|---|---|---|
| 承認待ち | 非活性 | 有効（確認後に申請を取り消す） | 両方有効 |
| 承認済み | 有効（本人申請のみ、権限は一般メンバー以上） | 非活性 | 承認は非活性／却下は有効 |
| 却下済み | 非活性 | 非活性 | 両方非活性 |

- 修正内容は**参加者一覧と同じ**：氏名・カナ・出欠（参加／欠席）・備考。区分はビジター固定。メールは表示／保存なし。
- API `visitor.modify` は既存の Worker LINE IDトークン照合→GAS member_ により、**登録元の `requestedByMemberId` が一致すること**をサーバー側で必須条件にする。他人の申請は取得も変更も不可。
- 修正は既存 `participantChange_` を同一 ScriptLock 内で再利用する。集金済みの人を欠席にすると集金記録を解除し、未確定の収支を再計算する。新しい返金概念は導入しない。
- 収支確定済み、対戦表作成済み、参加情報不整合、未完了の別操作のときは修正拒否。却下済みの修正／再承認は不可。
- 承認待ちの削除は `withdrawn` ステータスを記録し、参加者／集金には触れない。今後の承認を禁止し、申請者・管理者の通常一覧から非表示にする。監査アーカイブと操作IDは維持し、安全な再実行・版番号チェックを適用する。
- 修正・削除どちらも、保存前に `ビジター審査アーカイブ` にスナップショットを記録して `SpreadsheetApp.flush` を実行。承認済みの修正は `参加者操作アーカイブ` にも履歴を残す。

# v0.16.43 — 参加者一覧：LINE ID表示／本人情報固定／ビジター区分の分離

2026-11-18。検証環境のみ。本番未変更。シート列、既存ID、収支記録・集金記録・ビジター申請の構造変更なし。

## 参加者一覧（管理者・当番担当専用）
- メールアドレスは今後取得しない。参加者カード・修正フォームから完全に撤去する。APIも未取得のメール欄を返さない。
- カードには `LINE ID：U...` を表示する。出欠回答の参加者IDが `メンバー.memberId` と一致する場合にのみ `メンバー.lineUserId` を取得する。LINE IDのない参加者は「未紐付け」。重複したメンバーIDや形式の異なるIDは推測しない。
- ビジターはLINE利用登録不要。「LINE ID：なし（ビジター）」と表示する。登録した会員のLINE IDをビジター自身のものとして誤表示しない。
- 参加者一覧APIは既存の `requireDuty_` により、当番担当・管理者のみアクセス可能。一般会員に別会員のLINEユーザーIDを配布するAPIは追加しない。
- 修正フォームのメンバー／学生／当番担当／シャトル担当：氏名とカナは参照表示。出欠・区分（ただしビジター不可）・備考のみ編集可能。
- ビジター：氏名・カナ・出欠・備考は以前の v0.16.42 のとおり編集可能。参加区分はビジター固定。別途の申請者本人による修正画面にも影響しない。
- 参加者一覧にビジター新規登録は置かない。ビジター申請→管理者承認の経路のみ許可。
- 長押し「参加区分の変更」でもビジターへの変更は禁止。画面でビジター選択不可、GASの `category.set` と `participant.change` の双方で非ビジター ⇔ ビジターの切り替えを拒否する。

## 登録申請データの実態と扱い
- 現在の利用登録（`登録申請`、`メンバー`）は `displayName` を保持するが **カナ項目を保持していない**。
- 参加者一覧の氏名・カナの現行表示元は `出欠回答`。この変更では過去に記録された氏名・カナを勝手に書き換えず、修正フォーム上で編集禁止にする。
- 将来「利用登録の氏名・カナを参加者一覧へ厳密に自動同期」するには、利用登録時のカナ収集、参加者とのIDの紐付け、同期方針の別設計が必要。今回の変更で未実装の同期を実装済みと扱わない。

## 安全性・テスト
- GASは非ビジター参加者の `name` / `nameKana` を旧行から保存する。クライアントが別氏名を送信した場合も更新を拒否。
- ID衝突、本人IDと登録者IDの混同を回避する。LINE IDは画面表示・参照のみで、保存時の変更フィールドに含めない。
- 操作履歴の冪等性、変更前アーカイブ、集金済み区分変更時の再計算、確定済み収支と対戦表の修正禁止は既存仕様を維持。
- ステージングのCI回帰テスト後にのみ統合。GAS自動デプロイの対象は既存検証用のみ。本番は別承認。

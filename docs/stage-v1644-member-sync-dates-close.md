# v0.16.44 — 利用申請との照合・開催場所・登録日・閉じる位置の統一

2026-11-18。検証環境のみ。既存の本番LIFF／GAS／Worker／Google Sheetsは対象外。
既存シート列、ID、集金、対戦表、操作アーカイブは変更しない。

## 参加者一覧の表示
- 開催日プルダウンは `yyyy/MM/dd(曜日)　開催場所　HH:mm～HH:mm` の順。開催場所は `練習日程.place` を参照し、未設定ならその旨を明示する。
- カードは LINE ID、登録日、備考、修正・削除（右下）。メールアドレスは引き続き収集・表示しない。
- **会員の氏名の同期**：`出欠回答.participantId` と `メンバー.memberId` の完全一致で照合し、重複がない場合は `メンバー.displayName` を表示。LINE IDも同じ会員本人のIDを表示。ビジター申請者のIDは代用しない。
- **会員の登録日時**：`登録申請` の `status=approved`、`memberId`・`lineUserId` が本人マスタと一致する申請の `requestedAt`（利用申請日時）を表示。複数紐付け・未登録・旧データは「未記録」。練習参加回答日時ではないことに注意。
- **ビジターの登録日時**：`ビジター申請` で対象 `practiceId+participantId` が一意・`approved` の `reviewedAt`（管理者承認日時）を表示。申請日時は使わず、未承認・旧ルート等は「未記録」。
- 日時は画面上だけ `yyyy/MM/dd HH:mm`（JST）で統一。GASから送る日時ソースは変更しない。
- `出欠回答` に存在しない参加回答日時は推定しない。現在の利用申請にはカナ項目がないため、氏名カナは従来の `出欠回答` を維持する。
- 参加者一覧のメンバー修正フォームでは氏名・カナを引き続き編集不可。ほかの項目の保存時には保存対象の会員名をマスタから再照合し、その参加者行の古い氏名だけ同期する（監査アーカイブ／操作ID／収支確定・対戦表ロックは従来通り）。一覧の読取自体ではシートに書き込まない。

## 閉じる位置の全画面共通化
- 運用管理の全モーダル（確認／修正／管理／集金／日程／ビジター／エラー）は右上に `✕ 閉じる` を表示する。既存の「閉じる」ボタンは右上へ移動し、イベントハンドラを保持する。
- 「キャンセル／いいえ」しかなかったダイアログは右上に追加し、既存のキャンセル操作に委譲。確認／保存の取消処理と一時状態の解放を変更しない。キャンセル・実行アクションは従来のフッターに維持する。
- 処理中の全画面ロック（`stageBusyDialog`）には閉じるボタンを追加しない。手動更新／保存中の多重操作を禁止する。
- 対戦表の確認・エラー画面にも右上に閉じるを配置（確認時はキャンセル、エラー時は明示的な了解と同義）。QR発行の「閉じる」も右上へ移動。メインの一覧ページは全体のナビゲーション画面であり、独立した閉じるボタンがもともと存在しないため変更しない。
- 狭い携帯画面で右上の文字がタイトルに重ならないようスタイルとタップ領域を確保する。

## 境界と未解決データ
- 会員IDやLINE IDが一致しないレガシーデータには他人の情報を充てない。申請日・承認日が見つからなければ「未記録」。
- **利用申請日 ≠ 練習参加連絡日**。後者の実日時を必要とする場合は出欠回答のデータ構造と連絡元の記録処理を今後別途改修する。
- 検証用シートへのマイグレーションや既存登録情報の書き換えは行わない。

## 2. 旧業務仕様／新実装との関係（優先順位1・2を保護）

- 既存の区分順位は **メンバー → 学生 → ビジター → 当番担当 → シャトル担当**。区分内はカナ→正規化氏名→参加IDの順。LINE・集金・対戦表では**参加中の人だけを1から連番**。運用管理の参加者メンテナンスは欠席者も残す（人数・支払いを変更しない）。
- 新規申請は氏名1～30文字（空白除去）、カナ1～60文字。半角カタカナはNFKCで全角化し、全角カタカナ・長音・中黒を許可。カナ未入力やひらがな等は新規申請では拒否。
- 既存の古い登録（カナなし）や承認待ち申請は**移行時に架空カナを補完しない**。従来データは読み取り可能で、カナなしは氏名で代替。管理者の修正フォームでカナを追加可能。
- 承認時は新しい会員IDを発行し、「登録申請」の申請行と「メンバー」に同じカナを保存。LINE本人ID、申請日、権限、操作IDによる二重送信対策、退会中の新規申請禁止を維持。
- 管理者による既存利用者情報修正：氏名・カナだけ。既存のID・LINE ID、権限、利用登録日を維持し、**一意に一致する承認済み申請のみ同期**。ロック・旧値照合・競合拒否・監査を保持。過去の出欠・集金・収支・試合・退会履歴は書き換えない。
- 現在の一覧は**アクティブで一意な会員ID**に限って会員マスタ氏名・カナを表示時に重ねる。ビジターは出欠回答の氏名・カナを保持する。重複IDは他人の値に差し替えない。
- 参加者一覧で会員名・カナを直接変更させず、**同一会員の最新マスタ名・カナと照合して修正を受理**し、保存する参加者行の履歴上の旧カナは維持する。LINE本人出欠修正も同様。収支確定や対戦表ロックを省略しない。
- 収支残高 = 前行残金 + 集金額 - 支出。先行未確定行があれば翌月含め後続の確定不可（UIだけでなくGAS ScriptLock内でも拒否）。領収書・金種確認・操作ログに影響しない。

# v0.16.59 — 全画面の表示密度向上・集金ホームの参加者一覧だけスクロール

更新：2026/11/19。ユーザーから明示されたUI改善。v0.16.58の収支カード表示と既存の業務仕様を保ち、全画面の文字上下・カード・ボタンの余白をもう一段詰める。

## 表示変更・安全性

- **運用管理・参加者管理・ビジター・練習日程・収支・ダイアログ・試合進行/設定・QR閲覧**で共通stage-ui.cssを使い、文字サイズは維持しながら行間を従来1.5前後→1.34程度、説明文を1.4程度にする。カード・セクション間・案内メッセージ・タイトル・フォームラベルの上下余白を圧縮する。
- **ボタン**は上下paddingを狭めるが、主要な操作の最小タップ高さ44pxは残す。運用管理メニューは52px→46px（44px以上）。配色・フォーカス・disabled・イベントは変更しない。
- **収支管理表**はスマホ/折りたたみ端末（幅900px以下）のカード内余白を縮小。前月繰越、未確定3ボタン、確定済み当番/管理者の1ボタン、未来日禁止・確定順序・残高計算を維持する。901px以上の表形式も維持。
- **集金ホーム限定**：画面全体を100dvhに固定。タイトル、日付、開催情報、人数、処理不能理由と、下部の補正・支出・残高・確定ボタンは固定する。間にある参加者一覧「#list」だけ flex:1 1 0、min-height:0、overflow-y:auto、overflow-x:hidden とし、参加者が増えてもページ全体をスクロールしない。既存JSのscrollTop再読み込み復元はそのまま。
- 参加者のスクロール領域には role=region、aria-label、tabindex=0 を与えて、キーボードと読み上げでも識別できるようにする。
- **短い画面への安全例外**：高さ400px以下（横向き・ソフトキーボード時など）は、下部の金額操作を隠さないためホーム本体の縦スクロールを許容。一般的なスマホ縦長画面は参加者一覧だけスクロールする。
- **除外**：会員本人向けメニュー（body.visitor-member）と試合進行画面（.match-container）は、集金ホームの固定配置から明示的に除外し、それぞれ既存のスクロール方式を守る。これらにも**密度の改善のみ**は適用する。確認・編集ダイアログは従来どおり独立してスクロールできる。
- 変更は共通CSSと運用管理HTMLのアクセシビリティ属性。**GAS、Worker、集金チェック保存、収支順序・残高、認証/権限、氏名カナ、参加者並び順、出欠・試合履歴、Google Sheetsのデータは変更なし。**

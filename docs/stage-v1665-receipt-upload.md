# v0.16.65：立替精算・集金ホーム領収書アップロード／精算日の曜日／削除行再登録の判定

対象：検証環境のみ。2026/11/19。依頼内容を前回中断した後に再確認。

## 実装

- 立替精算の新規登録、および全体収支管理表の精算新規/修正で、精算日（ネイティブ日付入力）の下に日本語の曜日（例：11/28は「（土）」）を表示。保存/計算に使う yyyy-MM-dd は維持。
- 収支追加の「練習日（削除行を再登録）」は、単に全体収支表に収支行がないだけで活性化しない。操作履歴に **成功した ledger.change の delete 記録があり、現在対応するP-行が存在しない**開催日だけを候補にする。画面だけでなく、GAS更新時にも同じ条件を必須化。既存の開催日、過去の操作履歴、金額を改変しない。
- 集金ホームの「🧾 領収書登録」は、表示中の未確定練習日の収支行に紐付けてファイルをアップロード。添付済みなら「📄 表示」も可能。確定済みは追加/差し替え不可。
- 立替精算の新規登録と、全体収支管理表からの精算追加/修正にもファイル入力を接続。精算登録を先に保存し、その行ID/バージョンを確認して領収書だけ別APIで添付する。添付失敗時は既に保存済みの会計行を二重登録せず、失敗を明示して収支行の「修正」から添付し直せる。
- PDF/JPEG/PNG/WebP、**上限1.5MB**。検証用GASの実行主体が初回アップロード時に **非公開のDriveフォルダ**を自動作成し、ScriptPropertiesにフォルダIDを記録する。スプレッドシートIDが接続検証用（1XcsXwrPdRfDSPs8ibD7bfOGBM7zMxeSINFc9YlFBwac）と一致しない環境では領収書APIを禁止する。外部共有や公開リンクを作らない。
- WorkerがLINE IDトークンを検証し、GAS側で利用登録と当番担当/管理者権限を再確認。既存のScriptLock下でバージョンを確認し、ファイル参照IDは全体収支管理表の既存receiptFileId列に保存する。既存収支金額・確定順序・集金記録は変更しない。
- 参照もLINE/権限認証経由でファイル本体を取得し、ブラウザでダウンロードする。Web URL/Driveの共有設定から直接公開する仕組みは使わない。

## 注意・制約

- DriveAppを新たに使うため、**既存GASのOAuth権限にGoogle Driveへのアクセス許可が必要**。GitHub Actionsの成功だけで初回ファイルアップロードが動作することは保証されない。必要な場合はGASプロジェクト所有者による再認可が必要。本番反映前に検証用LINE実機から画像/PDFで試す。
- ユーザーのスマホ写真が1.5MBより大きい場合は、いったん圧縮する必要がある。現版は写真の自動圧縮を実装しない。
- アップロード済み領収書はDriveに保管する。収支行を削除しても証憑を誤消去しないよう、既存ファイルは自動削除しない。運用期間、保管費用、削除規則は本番移行前に定義する。
- データの移行・シート列の追加・本番設定変更はしない。既存シートのreceiptFileId列を使用。ユーザーの承認前に本番へのデプロイは行わない。

## 自動/実機テスト

- `tests/check-stage-receipt-weekday-v1665.cjs`：画面曜日表示、API認証ルート、ファイルサイズと形式、受信サーバー側バージョン/ScriptLock、削除操作の監査履歴に基づく再登録条件、キャッシュバスターを固定。
- 既存の収支確認順・集金・参加者・対戦表/退会/権限の回帰を維持。
- 実機では、(1) 精算日2026/11/28を選ぶと（土）が表示される、(2) 削除済み収支がない場合は「練習日（削除行を再登録）」非活性、(3) 未確定の練習日でJPEG/PDFを登録し「表示」できる、(4) 立替精算を添付付きで新規登録し、収支表の「修正」で表示・差し替えできる、を検証。金額変更を伴うテストは**架空データの検証環境でのみ**実施。

# v0.16.81 — 通信15秒・表示文言・異常時操作制御

2026年11月20日。検証環境のみ。旧アプリの確定順序・残高・監査・利用者権限・申請履歴を変更しない。

## 仕様の維持・変更・懸念

| 項目 | 既存動作 | 変更・安全策 |
|---|---|---|
| タイムアウト | 運用管理読取25秒・LINE初期化20秒。書込にはタイムアウトなし。対戦表/QR閲覧/Worker一部は無制限 | **全ての通信処理は15秒でユーザーへの応答を確定**。リクエストだけでなく応答JSON受信も対象。ブラウザは読取だけ中断し、**書込はサーバーで保存済みの可能性があるので中断も自動再送もしない**。 |
| 会計の部分失敗 | 収支行だけ保存済み／証憑未添付時の重複登録は禁止 | 維持。時間切れ/5xxの書込結果不明では管理操作を停止し、明示「更新」成功後だけ再操作可能。試合側の操作ID照合による再取得を維持。 |
| 集金画面 | 初回読込エラーが通常テキスト、重要メニューボタンの活性が不統一 | 専用赤枠に❌と短文。立替精算・領収書登録・運用管理は非活性、認証済み担当者の更新ボタンは活性、取得成功後だけ通常に復帰。 |
| 権限不足 | メンバーへ検証用権限切換の復帰案内を表示 | 本番では権限切換が存在しないため、権限不足の文言は「メンバー権限では運用管理機能を利用できません。」にする。検証専用権限切換ボタンは現在のまま保持。 |
| ビジター申請 | LINEリッチメニューの本人用導線（?visitor=1）、承認待ちの本人取消と承認後の管理者却下 | **変更しない**。一般メンバーの運用管理画面は操作禁止だが、別のLINEビジター申請/本人出欠経路は維持。承認後の参加者一覧での直接削除禁止を維持。 |
| メッセージ | 青処理・黄警告・赤エラーだが赤の絵文字なし。読込失敗が黄・通常テキストに混在 | **青：処理状況／回転表示、黄：⚠️警告、赤：❌エラー**の共通CSS。読込失敗は赤枠。業務上重要な確認文言は削らない。 |

## 統一した文言

| 場面 | 表示 |
|---|---|
| 読み込み中・保存中 | 「〇〇を読み込んでいます…」「〇〇を保存しています…」 |
| 読み込み15秒超過 | 「読み込みが15秒以内に完了しませんでした。「更新」で再確認してください。」 |
| LINE認証15秒超過 | 「LINE認証が15秒以内に完了しませんでした。LINEから開き直してください。」 |
| 書込の結果不明 | 「15秒以内に応答がありません。保存済みの可能性があります。「更新」で確認してください。」 |
| 通信失敗 | 「通信できませんでした。「更新」で確認してください。」 |
| 競合 | 「別の操作で更新されました。「更新」で確認してください。」 |
| 権限不足 | 「メンバー権限では運用管理機能を利用できません。」 |

対戦表の不正組合せで対象の選手/コートを説明する部分、領収書の収支保存済み・証憑未添付、退会確認などの事故防止に必要な説明は維持する。共通メッセージの簡潔化を理由に既存業務条件を省略しない。

## 15秒の対象と例外

- `live.js`：認証・会員確認・集金/収支/参加者/日程/現金/領収書/ビジター/権限の全API。読み込みだけAbort、書込は時間切れ時も原送信のサーバー処理が残る可能性あり。書込不確実時は明示更新まで再送禁止（自動8秒更新は解除しない）。
- `match.js`：対戦表の全APIとLIFF初期化。書込操作IDによる結果照合、二重送信防止を維持。
- `match-view.js`：閲覧専用のAPIとLIFF初期化。読取Abort可。
- `guest.js`：QR閲覧API。既存の15秒毎の定期取得間隔は**通信タイムアウトとは別**に維持。
- `cloudflare-worker/worker.js`：LINE IDトークン検証、GAS POST、Google ContentServiceへの転送GET/返信を**1つの15秒制限**で実施。既存の404時のGETだけの再取得は維持。元のGAS POSTを再実行しない。
- GASスクリプトのロック待ち15秒は変更しない。サーバー側で既に処理が始まった書込の取消・ロールバックを保証しない。

## テスト・実機

- 追加：`tests/check-stage-timeouts-message-v1681.cjs` により仮想時間で読取の15秒Abort、書込の15秒不確実扱い・二重送信しないこと、Workerの共同制限、エラー枠とボタン非活性を確認する。
- 旧会計の確定順序、残高、権限、退会、ビジター申請・取消と審査、対戦表、領収書の回帰テストは継続。
- [検証用運用管理LIFF](https://liff.line.me/2012602642-XBSkXduO)を使用。メンバー別テスターはLINEリッチメニューの既存ビジター申請/参加連絡入口から起動し、申請→未承認の本人引戻し→管理者側確認までを実機で検証。本番/実データで意図的な通信遅延や重複保存テストを行わない。
- 本番は事前承認制で、検証専用の権限切換は移行時に除外。CI/公開デプロイ成功と、実際のLINE本人認証を用いたE2E合格は区別する。

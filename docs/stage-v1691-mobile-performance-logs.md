# v0.16.91 — 実機通信時間からの読取軽量化・GAS内部計測拡張

2026/11/20。対象は**検証環境のみ**。ユーザー提供の診断スクリーンショット3枚に基づく。スクリーンショットに氏名・LINE ID・認証トークンはなく、文書にも保存しない。

## 1. 改修前の実機観測（ユーザー添付3枚、複数回操作）

| 呼出し | サンプル数 | 最短～最長 |
|---|---:|---|
| `/api/participant/list` | 2 | 4,985～10,504ms |
| `/api/cash/get` | 5 | 3,336～5,452ms |
| `/api/visitor/admin-list` | 3 | 3,154～4,639ms |
| `/api/overview` | 8 | 3,282～5,761ms |
| `/api/ledger` | 3 | 2,888～3,517ms |
| `/api/schedule/list` | 2 | 2,384～3,035ms |

- 11/20の3枚ではLINE照会（Server-Timing）は約9～73msの範囲。例えば参加者一覧10,504msの場合、LINE 9ms / GAS 10,242ms / **GAS POST 10,030ms** / GAS応答GET 212ms。
- `/api/overview` の診断例で、GAS内部計1,417～3,641ms、ロック待ち64～163ms。Workerが表示する **GAS POSTはGAS内部時間を包含**するため、単純加算しない。LINE認証/ロックを主因と断定する証拠はない。
- 最長の参加者一覧は2件中1件の値であり、継続的に10秒かかると断定しない。性能はコールドスタート/GAS起動/Google Sheets取得/Worker転送など複合要因。今回の最適化対象は**実装から確定できた過剰転送分**。

## 2. GASの安全な読取範囲削減

### `attendanceAuditDates_`（参加者一覧・本人参加連絡）

- 旧：`sheetRows_(ss,'操作履歴')` により、全件の **A:F 6列**（Fに操作結果JSONを含む）を読む。本人回答日時に必要なのは操作種別B、日付D、対象Eだけ。
- 新：存在シート・行数確認を維持し、B:E（**4列**）のみを取得。索引を対応付けし、`attendance.submit` 以外は無視。日時未登録/不正形式を無視する旧判定・first/last・同一対象の重複処理は維持。6→4列、巨大なJSON列Fを**読まずに済む**。シート本体・操作履歴を削除/変更しない。

### `visitorConfirmedPracticeIds_`（ビジター申請・管理）

- 旧：`entries_(ss)` で全体収支管理表A:P（16列）を取得し、公開済み練習収支の確定状態を抽出。
- 新：収支の **G:J 4列**（rowId, kind, practiceId, status）のみ取得。rowId空欄を除外し、`kind==='practice' && status==='confirmed'` 判定は従来どおり。確定済み月・日付/残高/証憑には触れず、同じScriptLockの中で毎回最新Sheetを参照。16→4列（当該履歴の取得セル量75%削減）。

### `cashGet_`（現金確認の参照）

- 旧：`entries_(ss)` により全体収支管理表A:P（16列）を取得して、その日の固定 `P-<practiceId>` のdate/balanceを使用。
- 新：必要なDate (A)、残金 (E)、固定rowId (G)を含む **A:I 9列**のみ取得。対象行を最初の1件とする既存の`.find`動作、日付不一致の `SETUP`、未作成の `found:false` とnull残高は維持。16→9列（当該取得セル量43.75%削減）。**現金保存 `cashSave_` は引き続き最新の全16列を読み、会計制約・楽観ロック・金種・監査を維持**。

これらは1回のSheet取得でのデータ転送列数削減であり、外部通信往復回数を減らすとは限らない。Google Apps Script実行時間の秒単位改善はまだ実機未確認。

## 3. 新しい選択式GAS内部計測

- `?perf=1`の時だけ、GASに `profileTimings:true` を送る読取対象を `/api/participant/list`、`/api/cash/get`、`/api/visitor/admin-list`、`/api/visitor/mine`、`/api/visitor/practices`、`/api/ledger`、`/api/schedule/list` に拡張。既存 `/api/overview` の内部時間取得は維持。
- GAS側の許可リストでも読取だけを対象にする。戻す内容はスプレッドシート取得・会員確認・ロック待ち・読取本体・GAS合計の**ミリ秒数だけ**。例外や認証失敗は結果を偽装しない。ユーザーID、氏名、トークン、スプレッドシートURL、書込本文、個人情報は計測に含めない。出力は既存の画面内「通信とGASの処理時間（検証用）」。
- 通常モードでは`profileTimings`を要求せず、返答もタイミング情報なし。既存の会計編集・集金・権限変更・ビジター承認・退会などの書込APIには診断パラメータを追加しない。通信15秒と不確定書込みの無断再送禁止を維持。
- `/api/participant/list`が再び10秒に近づいた場合、`GAS POST`、`GAS内部 合計`、`処理` の差でGoogle側の起動/転送待ちとシート読み込み処理を区別できる。内訳単独では完全な因果識別を保証しない。

## 4. 仕様保護・検証条件

- **不変更**：LINE本人認証、管理者/当番権限、GAS ScriptLock、操作履歴/エラー時復旧、v15の月またぎ・同日確定順序/残高、集金/現金保存の整合性、日程確定時収支行生成/11/21欠落行、試合進行/利用登録・退会、本番設定・Secret。
- 追加オフライン回帰：`tests/check-stage-read-columns-profile-v1691.cjs` は実GAS関数の投影読取、日付と金額、一意固定行ID、監査first/last、正常・異常系、不使用F列/財務列を模擬Sheetで確認。`tests/check-stage-read-profile-ui-v1691.cjs` は実UI診断描画、PERF_MODEのみの表示とread-only許可リスト、書込payload不変を確認。
- 既存の出欠・参加者・ビジター・会計/集金・現金・権限・対戦表・退会・Worker/公開配信はフル回帰CIで検証。CI通過しても実機の前後比較完了とはしない。
- 実機確認：検証用 [性能診断LIFF](https://liff.line.me/2012602642-XBSkXduO?perf=1) を開き、11/25と11/28の参加者一覧（10件/日、出席8/欠席2、既存対戦表ロック）と現金確認、ビジター管理、収支一覧を読み込む。数値のみ報告し、個人情報やLINEトークンを送らない。前後の測定条件が違えば速度改善の比率を断定しない。

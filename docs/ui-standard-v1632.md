# 全力☆スマッシュ — 共通画面仕様（再確認） v0.16.32
2026-11-17。過去のユーザー確定事項とステージング記録に基づく。既存運用管理・対戦表・退会検証画面の共通基準。

## 処理中／自動更新
- **初回読み込み・手動更新・保存・変更送信**は、中央の白い角丸ポップアップ、スピナー、短い状態ラベルのみを表示して、背景のボタン・入力などの操作をブロック。
- 表示ラベルは基本「読み込み中です…」「処理中です…」。処理に応じた短いラベルは可。
- **「処理が完了するまで操作できません」「操作が完了するまでお待ちください」「完了まで操作できません」等の補足説明は表示しない。**
- 処理中表示専用ダイアログの自動フォーカス枠（黄色等）を出さない。操作ボタン・入力のキーボードフォーカス表示は維持。
- **バックグラウンドの自動更新では全画面ロックしない。** 編集中・ダイアログ操作中の描画割り込みを避け、保存中は自動更新を抑制する。
- 二重タップ・同時送信を防止。処理完了・失敗時にロック解除。エラー表示とスピナーが重ならないようにする。

## 確認・結果・競合
- 変更操作は、ブラウザ標準の `alert()/confirm()` ではなくアプリ内の中央確認ポップアップで事前確認する。原則、キャンセル／実行の選択肢。
- キャンセル時に変更APIを呼び出さない。権限変更の未保存プルダウン選択は維持し、手動更新でサーバー値に戻す。
- 保存成功はサーバーからの応答**と再読み取りで検証後**に、短い画面下部の成功トーストを表示。
- エラーはトーストでなく**閉じるまで残るアプリ内エラーダイアログ**。失敗時の状況を分かりやすく表示し、エラー中のEscapeは無効化する。
- 通信エラー・タイムアウト・HTTP 409：変更APIの自動再送をしない。結果不明時は読取専用の再取得で状態を確認し、ユーザーに再確認を促す。
- 表示だけの成功イベント（例：QR閲覧用画面を開く／QRを表示しただけ）に不要な成功トーストを出さない。

## 見た目・配置・入力
- 運用管理ツールの既存のデザイン・モーダル・レイアウトを基準として統一。青は操作可能、灰色は非活性（確認ポップアップの危険操作は明確に区別）。
- 高齢者にも分かる短い日本語ラベルで、余計な注意書きを増やさない。スマートフォン表示を優先する。
- 標準目安：タイトル17px、本文15px、主要ボタン14px、入力16px、表13px。操作可能な主要ボタン・セレクトは高さ原則44px以上。
- ヘッダーは左に画面タイトル、右に更新ボタン。開催情報は「第N試合進行中」表示の上。
- 表示日付は `yyyy/MM/dd(曜)`、日時は `yyyy/MM/dd(曜) HH:mm`（日本時間）。内部データのISO形式は変更しない。
- 操作権限に応じて、管理者・当番担当・一般メンバー・ビジターの表示／操作を分ける。見た目の非表示だけでなくAPI側でも認可する。

## v0.16.46：閉じる・更新・追加の配置統一（検証環境の接続画面）
- **画面／モーダルのヘッダー**：左にタイトル。右の同じ操作領域に、**「追加」→「更新」→「✕ 閉じる」**を配置（存在する操作だけを表示）。「閉じる」は最右端。追加／更新に保存や確定の意味を含めない。
- **幅が足りないスマートフォン**：タイトルの下に操作領域を折り返して表示する。操作ボタンを重ねる、固定座標にする、負のマージンで上へ移すなどの実装は禁止。44px以上のタッチ領域と各ボタン間の余白を維持。
- **リスト／フィルター**：開催日プルダウンや収支の対象月・前月・翌月はヘッダーの下に配置。画面全体に対する「追加／更新」はヘッダー。ビジターの「自分の申請」のような**部分一覧専用更新**は、その部分見出しの右側に配置し、全体更新と混同させない。
- **フッター**：入力フォームのキャンセル／保存、確認のキャンセル／実行、危険な削除／却下／確定は下部に残す。「✕ 閉じる」は従来のキャンセルと同じ処理を呼び、保存・変更APIを実行しない。
- **処理中ポップアップ**：全画面ロック中は右上閉じるを出さず操作できない。エラー画面は閉じるまで残る設計を維持する。
- **機能退行防止**：元のボタンのIDとイベントハンドラを維持する（別のボタンを見た目だけで代用しない）。DOM移動後も更新・追加・保存・取消・権限判定が動作することを確認。新しい画面に操作を追加する場合はボタンの存在・順序・押下可能性をテストへ反映する。
- **実装**：`dialog-close.js`、`stage-ui.css`、対戦表／QRのヘッダーに同じ方針を適用。対象は検証用の接続された運用管理／対戦表画面。未接続の退会単独検証ページへの適用は運用試験と分ける。

## v0.16.48：ダイアログ／収支／メンバー権限管理のデグレード防止

- **右上の「✕ 閉じる」は画面レベルの管理ダイアログだけ**。修正フォーム、確認／削除／保存／エラーのポップアップには追加しない。従来のフッターにあるキャンセル・確認・閉じる操作を維持する。対戦表の確認ポップアップも右上の追加ボタンを撤去。
- 管理画面ではヘッダー左に画面名、右に追加／更新／閉じる。ポップアップは見出しと最下段の確認ボタンのみ。押下領域44px以上、幅不足時は折り返す。
- 収支表の行操作は **修正＝青／確定＝緑／削除＝赤／解除＝グレー**。右寄せで配置し、タップ領域を重ねない。
- 収支の確認メッセージは `【収支の確定】` 等の見出し、本文「yyyy/MM/dd(曜)　対象名」「確定しますか？」の2行とし、保存前の最小限の情報に留める。日程確定の表示も日付＋場所＋確認文。
- 「練習日（削除行を再登録）」は、過去／当日で有効かつ対応収支行が存在しない日程がある場合にのみ選択可能。候補なしでは登録区分の option を disabled にし、送信側もガードする。
- 練習日程マスタで日程を確定したら、同一ScriptLockで日程IDに紐づく **収支行を一意に自動作成** する。収支の既存確定残高が変わらないよう再計算を実施。未来日でも未確定・0円の行として作成し、全体収支表の翌月以降にも閲覧できる。開催日以前の集金は引き続き禁止。
- 通常の検証用運用管理LIFFは改良版権限管理を標準使用（旧版は `?accessUi=legacy` での診断ロールバックのみ）。`メンバー権限管理` の `利用者一覧` は参加者一覧と同構造のカードを使用し、名前・権限・有効状態・LINE ID・利用登録日を表示する。管理者本人・最後の管理者・停止中メンバーは変更不可。
- 退会履歴は初期表示から `退会者一覧` にカードで表示する。履歴が0件なら「退会者はいません。」、APIが履歴を返せなければ「退会履歴を取得できません。」を表示し、空と未取得を混同しない。
- 検証専用に限定。本番環境／実退会の有効化／Worker設定は別途変更しない。追加チェック：`check-stage-dialog-close-v1644.cjs`、`check-stage-finance-member-v1648.cjs`、`check-stage-schedule-v1638.cjs`。

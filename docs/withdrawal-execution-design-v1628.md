# 全力☆スマッシュ v0.16.28 — 退会実行の最終設計（レビュー用・未デプロイ）
更新日: 2026-11-17

## v0.16.27 実機試験合格
- ユーザーからステージングWorkerの`/health`で`version=0.16.27`が期待どおりと報告された。
- LINEから「サーバー側の退会条件を確認」を実行し、登録管理者：1名／退会候補：0名／退会処理：無効（今回実行しません）／現在、退会可能な対象者はいません。と表示を確認。
- `member.manage.withdraw`はWorkerとGASで常時拒否するv0.16.27のまま。今回も有効化していない。

## 次工程に向けた設計確定事項
- 実行者はLINE IDトークン検証を経た**有効な管理者**。GASでLockService取得後に再度認可する。
- 退会できるのは有効な一般メンバー・当番担当のみ。管理者は人数によらず対象外。実行者本人も対象外。
- メンバーIDとLINEユーザーIDの重複・形式、履歴の`processing`/`completed`を検査。対象ID再入力・一意の操作IDを要求する。
- シートを更新する場合、まず`退会履歴`に名前・操作ID・`processing`を記録し、直ちに対象の有効フラグをfalseにする。
- 本人発行の未失効QRを失効し、当番所属と登録申請を整理したあと履歴を`completed`にする。最終的に旧メンバー行を削除して監査を記録する。
- 出欠、集金、収支、試合、既存監査は保持。旧表示名は退会履歴で解決し、新規登録者は新しいメンバーID・一般メンバーとして承認する。
- GASへのPOSTはWorkerで再試行せず、通信不確実性や`processing`状態で自動再実行しない。完了前の障害は管理者の手動照合・修復対象。
- v0.16.27の`member.status` / `member.apply` は途中退会時の状態表示と申請拒否を整合させる修正が必要。v0.16.18の検証実装を基準に再検証する。
- LINEのユーザー単位リッチメニューを解除しても、デフォルトメニューが表示され得る。見た目ではなくGASの認可を権限保護とする（LINE公式資料参照）。
- Worker/GASにおける`WITHDRAW_ENABLED=false`、`RICH_MENU_SYNC_ENABLED=false`は維持し、元ステージングの退会実行は引き続き不可能。
